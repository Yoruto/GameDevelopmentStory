# 前辈 / 后辈 / 同事 三条关系线重设计方案

> 对象：`activity/career-world.json` → `eventLines.lines` 中 `bond-mentor` / `bond-peer` / `bond-junior`
> 引擎：`h5/js/sim/careerLines.js`（事件线驱动）、`h5/js/sim/career.js`（bond 记录与共存判定）
> 结论先行：**三条线的"生硬"不来自文案，来自机制**。选择没有回声、设定没有接上、节奏被主线挤死。

---

## 0. 现状体检

### 0.1 三条线速览

| 线 | id | 拍数 | 开线条件 | 基调 | 结尾 |
|---|---|---|---|---|---|
| 前辈线 | `bond-mentor` | 8 | 同栋 18 月 + 每年掷 42% | 受教 → 独立 → 提名 | 跟前辈走 / 留下 |
| 同事线 | `bond-peer` | 8 | 同栋 24 月 + `rank≥3` + 每年掷 30% | 全程较劲 | 7 选 1（晋升/同升/换岗/调组/跳槽/挖人/史诗） |
| 后辈线 | `bond-junior` | 6 | 从业 36 月 + (`rank≥4` 或 1 部署名) + 每年掷 34% | 教 / 不教 | 留组 / 推荐走 / 被挖走 / 拦下 |

### 0.2 九个机制性问题（按严重度）

**P1 · 选择没有回声（致命）**
三条线 22 拍里，选项写入的 flag 有 `apprentice` / `voice` / `credit` / `taught` / `taughtWell` / `remote`，**没有任何一处被读回**。
核对整份 `eventLines`：写入 flag 的 `setFlags` 有 19 处，而读取 flag 的 `skipIf`（`flagOn` / `flagOff` / `notHeld` / `notCollapse`）**只有 1 处**——`epic-title` 的 `beats[1].skipIf.notHeld`，配对 `beats[0]` 的 `setFlags.held`。引擎能力是好的（`careerLines.js:450-453`），史诗线也用对了，但**关系线一个都没用**。
→ 前辈线选"照着做"还是"改成自己的"，除了当场 `+honor` / `+fame` 的差别，后面 5 拍完全相同。玩家能感觉到"我的选择被吞了"，这是"生硬"的第一来源。

**P2 · 后辈的揭晓只挂在回国线上**（2026-09-18 修正）
`revealJunior` 唯一的触发点是 `era-return-china` 的 `beats[1]`「小T 的现在」，条件是：2010 年后 + 38% 年掷 + 玩家在「国内来信」选了「看看」+ 后辈 bond 已存在。
→ **后辈线自身在 `finale`（小T 往哪走）就结束了**：他留组也好、被挖走也好，这条线都不会再交代"他后来成了谁"。玩家带过一个人，却不知道他后来怎样——而这恰恰是后辈线唯一的情感落点。揭晓被外包给了一条独立、低概率、时代限定的线。

**P3 · 三条线共用一个车道**
`eventLines.maxBeatsPerMonth = 1`、`maxNewLinesPerMonth = 1`。三条 bond 线要和 `company-merger`(80)、`become-producer`(20)、`promotion`(10)、`epic-title`(7) 抢这唯一的 1 拍，而它们的优先级只有 6 / 5 / 4。
→ 生涯主线一活跃，关系线全被饿着；三条关系线之间也互相饿死。

**P4 · 开线靠每年抽奖**
`startChance` 0.42 / 0.30 / 0.34 + `retryNextYear`。条件满足后每年掷一次，没中就再等一年。
→ 玩家无法预期，也无法经营。关系线的开始是"冒出来的"，从第一拍起就缺乏心理准备。

**P5 · 异地只有换句文案**
共存翻转 → `remotePending` → 弹一次 `remoteBeat`（三条线都是同一句"还联系吗"二选一），之后仅 `bodyRemote` 替换文本。`setFlags:{remote:true}` 本身也是死 flag。
→ 分离这个最有戏剧张力的节点，被压缩成一个提问框。

**P6 · 关系线在 UI 上没有落点**
全项目没有关系面板 / 人物卡，`{mentorName}` `{peerName}` 只出现在弹窗里。
→ 玩家对一个突然出现的陌生名字没有任何认知入口，情感投入无从谈起。

**P7 · 同事线基调单一 + 结尾功能化**
8 拍中 6 拍是"较劲"（抢交付 / 对照表 / 抢署名 / 观察名单 / 通宵对打 / 关键交付），没有和解、没有变质、没有转折。
`finale` 7 个选项里 6 个是职级与公司操作（晋升 / 双升 / 换岗 / 调组 / 跳槽 / 挖人）——把"职业分叉"的职能塞进了同事线结尾。
→ 一条情感线以功能菜单收尾，这是"生硬"的直观来源。

**P8 · 前辈线尾拍可能静默完结**
尾拍 `leave` 依赖 `wait.type = bondDepart` 且 `skipIf.noMentorSuccessor`。若当前公司 `seniors[0]` 没有 `successorCompanyId`，或落到"占位导师"（`id: null`，`career.js:699`），该拍被跳过；因为它是最后一拍，`advanceSkippedBeats` 直接 `completeLine(done)`。
→ 玩家在毫无察觉的情况下"走完了"前辈线。

**P9 · 时间尺度错配**
单拍间隔 2–4 个月，但被 1 拍/月预算挤，一条线实际横跨数年。前辈线的 `nominate`（提名晋升）要求玩家还在原公司，实际到那时多已异地，选项被 `skipIf` 摘掉。

## 1. 角度 A · 让选择有回声（改造优先级 P0，纯配置）

设计"三段回声"，全部可用现有字段实现，**不需要改引擎**：

| 回声层级 | 延迟 | 实现方式 |
|---|---|---|
| 立刻回声 | 当拍 | `option.effects` 数值差 + 选项文案本身分叉 |
| 中期回声 | 2–3 月后 | 新增一拍，用 `skipIf: { flagOff: "voice" }` / `{ flagOn: "owner" }` 分出两个版本 |
| 长期回声 | finale | 选项可见性与文案随 flag 变化（`skipIf.flagOn/flagOff`） |

**前辈线示范**（`voice` 已经存在，只需补读回）：

```json
{
  "id": "review-after-voice",
  "wait": { "type": "months", "n": 3 },
  "presentation": "notice",
  "speakerBond": "mentor",
  "kicker": "前辈线",
  "title": "评审席上的那句话",
  "skipIf": { "flagOff": "voice" },
  "body": "评审时有人问这版像谁。你说按自己的说法铺的。{mentorName} 没接话，会后把这句话记进了纪要。",
  "effects": { "fame": 1, "jobXp": 1 }
}
```
再补一拍 `skipIf: { flagOn: "voice" }` 的变体（`body` 写"你说照前辈的骨架走"），把 `voice: "misor"` 之类也纳入。

**同类改造点**：`credit`（同事线署名）→ finale 时"摊开"过的玩家可解锁 `dual` 共同晋升的更好结局；`taughtWell`（后辈线教法）→ 决定 P2 中揭晓时的文案走向。

## 2. 角度 B · 给每条线一条"弧"，而不是一串"点"

现状是**点串**：8 个节点彼此独立，只有时间先后。应改为**弧**（有意向、有转折、有代价）：

### 前辈线 · 从"受教"到"反哺"
```
拜师 → 挨改（羞辱感） → 想摆脱他 → 决裂边缘 → 和解或超越
     → 反哺（前辈被时代甩下，需要你） → 送别
```
关键补强：**加"反哺"段**。现在的前辈线是单向的（他给你），到 `stand` 就单方面结束了。让前辈在某一年遇到瓶颈（`minYear` + 你职级更高时触发），由你决定"还他一次"——这才是完整的关系。

### 同事线 · 从"较劲"到"承认"
```
结梁子 → 被迫合作 → 挡刀或甩锅 → 互相认可 → 关键抉择 → 和解 / 反目 / 失联
```
关键补强：**插入"被迫合作"与"互相认可"两段**，把 8 拍里的 6 拍较劲压到 3 拍，腾出空间给转折。较劲连打 6 次不叫张力，叫重复。

### 后辈线 · 从"复制品"到"另一个人"
```
收徒 → 抄清单（他抄了你的坏习惯） → 他想成为你 / 想超过你
     → 出走或留守 → 揭晓（他做出来了什么）
```
关键补强：**接上 P2 的揭晓**，把 `revealJunior` 放在"他走了之后的第一部作品发售"这个节点，情感落点最强。

## 3. 角度 C · 拆车道，别让关系线和晋升抢闸门（需小改引擎）

三个可选方案，按投入递增：

**C1 · 独立车道（推荐）**
新增 `eventLines.bondBeatsPerMonth = 1`，`processCareerLines` 里给 bond 线单独一份预算，与主线 `maxBeatsPerMonth` 并行。
改动点：`careerLines.js` 的 `processCareerLines`，把 `ready` 数组按 `def.kind === "bond"` 拆成两条队列各自计算预算。

**C2 · 亲近度驱动替代年掷**
用已有的 `bond.monthsTogether` 做驱动：把 `startChance` 从"每年掷一次"改为"每 N 个月必到"（如 `maxMonthsTogether` 强制开线）。
让关系线的开始变得**可预期**，玩家能看到"和这个人待久了，事情就会发生"。

**C3 · 在役窗口**
给每条线设 `windowMaxMonths`：超过窗口（比如 60 月）仍未开线则永久不再开，把机会让给新公司的新关系。
现状的问题恰恰相反：开线条件一旦满足就无限期等待，导致关系线在错误的时机（早已跳槽）才触发。

## 4. 角度 D · 把关系从"剧情"升级为"系统"（收益最大，改动最大）

现状：关系只是一个"事件序列 + 若干数值奖励"。建议引入两条隐性轴：

| 轴 | 含义 | 增减来源 |
|---|---|---|
| `trust` 信任 | 对方愿不愿意为你做事 | 帮过他 / 甩锅 / 公平署名 / 抢功 |
| `tension` 张力 | 关系的紧张程度 | 抢交付 / 竞争晋升 / 长期异地 |

作用：
- `trust` 高 → 前辈真的写推荐信（跳槽 offer 质量提升）、同事愿意共同晋升、后辈成名后回来给你机会
- `tension` 高 → 关系线出现"决裂"分支、finale 的负面结局
- 两轴都由已有 flag 派生即可，不必新增字段存储（先由 flags 推导，验证有效再落成独立字段）

这样三条线各自长出一条**收益轴**，与主线的三个资源对应：

```
前辈线  →  成长（主职维 / 跳槽质量）
同事线  →  竞争（职级速度，但有代价）
后辈线  →  名声（长期回报，兑现最晚）
```

## 5. 角度 E · 给三个人"落地"（UI，P1）

- **关系卡**：HQ 侧栏或履历页加"同僚"区块，显示三个人当前的 `colocated` 状态、最近一次互动、关系倾向（`trust` / `tension` 的可视化条）
- **名字预热**：`pinCareerBonds` 已经钉好了 mentor / peer，可以在入职首月就做一次轻量介绍，而不是等到第 18 个月突然"把你叫到工位旁"
- **异地可视化**：异地时卡片明确显示"两个城市"，配合 P5 的玩法改造

---

## 6. 角度 F · 异地要有玩法，不是换文案（P1）

系统里已有三个钩子，但没串起来：`returnInvite`（回国线）、`peerEpic`（去搭同事的史诗作）、`mentorSuccessor`（跟前辈走）。

建议把"异地"做成一个**可持续状态**而非一张二选一问卷：

| 异地行为 | 成本 | 收益 |
|---|---|---|
| 保持联系 | 少量时间（如当月 `mainStat` 不涨） | `trust` 维持，保留后续钩子（挖人 / 被挖 / 重逢） |
| 定期交流技术 | 中 | `jobXp` 微涨，知道对方在做什么（情报） |
| 断联 | 无 | 关系线提前收束，但腾出第二条车道 |

关键：**异地不等于关系结束**。现状的 `remoteBeat` 选"就此别过"就 `complete` 整条线，而选"还联系"也只是让文案多一句 `bodyRemote`。

---

## 7. 角度 G · 结尾不该是功能菜单（P1）

同事线 `finale` 的 7 个选项应拆成两拍：

1. **关系收束拍**（情感）：和解 / 继续较劲 / 反目 / 失联
2. **职业去向拍**（功能）：晋升 / 换岗 / 跳槽 / 挖人

并让第一拍的结果影响第二拍的可用选项——这就是最小规模的关系线"闭环"。

同时给每条线补齐 3 种关系收尾，不留静默完结（P8）：

| 线 | 和解 | 反目 / 断裂 | 失联 |
|---|---|---|---|
| 前辈线 | 反哺 + 送别 | 前辈公开否定你 | 公司倒闭自然散 |
| 同事线 | 共同晋升 | 抢晋升撕破脸 | 各奔东西 |
| 后辈线 | 他成名后来找你 | 拦他跳槽，从此不见 | 走着走着就没了 |

## 8. 落地路线（三档）

### 档 1 · 低成本（只改 `career-world.json`，无引擎改动）
1. P1 选择回声：每条线补 2–3 拍 `skipIf.flagOn/flagOff` 的变体
2. P2 后辈揭晓：在 `finale` 之后补一拍带 `effects.revealJunior`
3. P7 同事线拆结尾：`finale` 拆成关系拍 + 去向拍，削掉 2 拍较劲、换成"被迫合作""互相认可"
4. P8 前辈线兜底：给 `leave` 补一个不带 `noMentorSuccessor` 的替代尾拍
5. 文案层：把 `startChance` 调高、间隔缩短，让节奏在体验上先不明显地挤

**预期收益**：最大，成本最低。P1 + P2 修完，"生硬"感会去掉大半。

### 档 2 · 中等（config + `careerLines.js` 小改）
6. C1 独立车道
7. P5 异地玩法（补 `remoteBeat` 之外的异地拍）
8. D 的 `trust` / `tension` 先以 flag 推导形式落地

### 档 3 · 结构性（含 `career.js` / UI）
9. E 关系卡
10. D 两轴落成正式字段，并驱动主线（跳槽 offer 质量 / 晋升速度 / 后辈回报）

## 10. 实施记录（2026-09-18）

### 10.1 后辈线改名：小T → 小满

原名字的两个问题：字母代号感（不像中文团队里的叫法）；正文里 13 处**硬编码**"小T"，改字段改不动文案（`bonds.juniorAliasThen` 只用于说话人标签）。

处理：
- `bonds.juniorAliasThen` → `小满`
- 正文 11 处硬编码改为 `{juniorName}` 占位符 → 文案随揭晓自动在"小满 / 真名"之间切换
- 两处刻意的例外：揭晓拍标题保留旧名写法（`小满的现在`），回国线的揭晓句保留"当年的小满"（揭晓需要"旧名→新名"的对照）
- 开线第一拍原来是"新人自称小T"，"自称"配字母代号最生硬，改写为"组里来了个新人，说自己叫{juniorName}，总往你工位这边看"

### 10.2 三条线的拍结构

| 线 | 改前 | 改后 | 变化 |
|---|---|---|---|
| 前辈线 | 7 拍 | **10 拍** | +voice 回声 ×2、+兜底尾拍 |
| 同事线 | 7 拍 | **10 拍** | −观察名单/−关键交付、+被迫合作、+credit 回声 ×2、+互相认可、finale 拆关系/去向两拍 |
| 后辈线 | 6 拍 | **10 拍** | +taughtWell 回声 ×2、+揭晓拆成『响铃 + 接起』两拍 |

具体见下方"已落地"清单。

### 10.3 已落地（档 1，全部为 `career-world.json` 配置改动）

1. **P1 选择回声**（三条线全部接上）
   - 前辈线：`voice` → `mirrorStyle` / `ownStyle`，新增 `voice-echo-mirror`（像谁的手笔）/ `voice-echo-own`（这不是他的写法）
   - 同事线：`credit` → `creditShare` / `creditMine`，新增 `cred-echo-share`（两个人的名字）/ `cred-echo-mine`（只有你的名字）
   - 后辈线：`taughtWell` 原本就是布尔值、天然可读回，新增 `teach-echo-well`（他把清单改了一版）/ `teach-echo-rough`（他又绕了远路）
2. **P2 后辈线自身收束到揭晓**：`finale` 的 4 个选项去掉 `complete`（改 `advance`），尾部新增 `reveal` 拍（`effects.revealJunior`），文案用"当年工位旁边总来问问题的那个新人"指代旧身份、`{juniorName}` 给真名——不硬编码旧名，机制上更稳
3. **P7 同事线补弧**：删掉 `review-shadow`、`key-delivery` 两个纯较劲拍；`all-nighter` 从"通宵对打"改写为"同一间会议室"（共渡难关）；新增 `forced-coop`（被迫合作）、`respect`（他先开了口）；`finale` 拆成 `finale-relation`（关系收束：握手/接着较劲/散了）+ `finale-path`（职业去向：原 7 选项）
   - 关系与去向联动：选了"散了"（`peerSplit`）之后，`finale-path` 里需要关系在的选项（`dual` / `epic` / `peer-comes`）通过 `skipIf.flagOn: peerSplit` 自动隐藏
4. **P8 前辈线尾拍兜底**：`leave` 之后新增 `part-ways`（工位空了，无 `skipIf`）。原行为是 `leave` 作为最后一拍被 `noMentorSuccessor` 跳过时，`advanceSkippedBeats` 直接 `completeLine(done)` —— 玩家看不到任何结局
5. **文案去重（顺带修的既有问题）**：UI 把带 `speakerBond` 的拍渲染成 `名字：「body」`，而 body 又以同一个名字开头，实际渲染成 `小满：「小满 把你写的清单抄走了…」`。修了 12 拍 / 19 处（三条线里"body 以人物名开头"的全部），改为无主语句；名字出现在句子中部的保留，避免过度改写

### 10.5 后辈线揭晓改写：一通陌生又熟悉的电话（第二轮）

原揭晓是"一份行业署名文件摊在桌上"——被动、第三人称、没有声音。改成**两拍同月连弹**：

| 拍 | id | wait | 作用 |
|---|---|---|---|
| 1 | `call` | `months: 18` | 陌生号码打来，**刻意不提名**（这一拍里不出现 `{juniorName}`），只留"号码陌生，声音一下就熟了" |
| 2 | `reveal` | `sameMonthChain` | 接起来，报出名字，`effects.revealJunior` |

- **为什么拆两拍**：`sameMonthChain` 让第二拍在同一个月里接着弹（`careerLines.js:350 / 741 / 840`），**不额外占** `maxBeatsPerMonth` 车道。"陌生号码"单独占一屏，紧张感才不被叙述句稀释；挤成一屏就只剩"交代信息"。
- **`n` 从 4 改到 18 个月**：原来 4 个月后就说他"被整个行业这么叫"，时间尺度撑不住。
- **按异地/当面分叉**（`body` / `bodyRemote`）：他已离队走 `bodyRemote`（直接来电）；仍在你旁边则用 `body` 先补一句"他后来还是走了"——否则"一通陌生电话"在叙事上不成立。
- 揭晓拍追加 `effects.juniorLeave`，让"他走了"和状态一致（否则会留下"人走了却仍判定坐在旁边"的隐性矛盾）。
- **回国线的揭晓降级为兜底**：新增 `skipIf.juniorRevealed` 条件，后辈线已经揭晓过就不再演第二遍反转；同时去掉该拍的 `speakerBond`（UI 会渲染成 `真名：「…真名…」`，名字重复）。

#### 顺带修掉一个真实 bug：`juniorLeave` 会被下一回合回滚

`applyCareerJuniorLeave` 只设 `colocated = false`，而 `refreshCareerBondColocation` **每回合**按"老家公司 == 现公司"重算 `colocated`（`career.js:660`）。实测：

```
选 recommend 当帧   junior: colocated=false  home=triAce  company=triAce
tickMonth ×1        junior: colocated=true   home=triAce  company=triAce   ← 又坐回来了
tickMonth ×2 / ×3   junior: colocated=true   …                                ← 一直是 true
```

即"推荐去别的工作室 / 被挖走成全"这两个结局里**他并没有真的走**——线上的 `remoteBeat`（还联系吗）与所有 `bodyRemote` 文案因此永远不会触发。

修法：`applyCareerJuniorLeave` 落一个持久标记 `junior.departed = true`，`refreshCareerBondColocation` 尊重它：
`now = bond.departed ? false : companyOrSuccessorMatch(home, playerCo, config)`。只有剧情显式判过离队才置位，其它 bond 行为不变。

### 10.6 电话触发加准入：他所在的公司已成立 + 有在研目录作（第三轮）

需求：**那通电话不能凭空打来**——他得有拿得出手的新作，而且那家公司得真的存在。

#### 为什么必须判"公司已成立"

后辈身份在开线时由 `bonds.juniorRevealPool` 三选一抽定（`career.js:951`），公司/人/作品**同源绑定**：

| 后辈真名 | 公司 | 成立年 | 揭晓作品 | 作品开发期 |
|---|---|---|---|---|
| 大伟哥 | 米哈游 | 2011 | 崩坏学园2 | 2012-09 ~ 2014-03 |
| 海猫络合物 | 鹰角网络 | 2017 | 明日方舟 | 2017-05 ~ 2019-05 |
| YY | 叠纸游戏 | **2013** | 暖暖环游世界 | **2012-06** ~ 2013-12 |

最后一行就是问题所在：**暖暖环游世界的开发期比叠纸的成立年还早半年**。只按"作品窗口"判准入，会造出「他 2012 年就在叠纸做暖暖」这种时间线上不成立的事。所以准入门禁是**两个条件**。

#### 实现

引擎新增两个判定（`careerLines.js`），准入规则写在配置里可调：

```json
// eventLines.bonds.juniorCall
{ "requireFounded": true, "requireInDev": true }
```

| 位置 | 作用 |
|---|---|
| `beatWaitReady` 的 `months` 分支：`wait.juniorInDev` | 等够 `n` 个月后**每月复查**：公司已成立 + `companyInDevCatalogTitle()` 非空才放行；不满足就继续挂着，不占月度车道 |
| `skipCondHits`：`skip.juniorCallGone` | 收掉"等不到的电话"：公司已成立、当月无活、且它所有目录作的发售月都已过去 → 跳过 `call` + `reveal`，线在 finale 正常 `done`（不留永久挂起的拍） |

`call` 拍 `wait` 改为 `{ "type": "months", "n": 18, "juniorInDev": true }`；`call` / `reveal` 两拍都带 `skipIf: { "juniorCallGone": true }`（`reveal` 是尾拍，被跳过时 `advanceSkippedBeats` 会 `completeLine(done)`）。

> 范式不是新造的：前辈线的 `wait.type = "bondDepart"`（`careerLines.js`）早就在做同一件事——"等 mentor 走了 + 新东家当月真有在研目录作"。本次只是把它复用到后辈电话上，并补了"永远等不到怎么收场"。

#### 实机判定（探针 + 真机，全绿）

| 场景 | 结果 |
|---|---|
| 1997 + 米哈游（公司未成立） | 不响 |
| 2013 + 鹰角（2017 才成立） | 不响 |
| 2013 + 米哈游（崩坏学园2 在研中） | 响 |
| 2020 + 鹰角 | 响 |
| 2035 + 米哈游（窗口已关） | 不响，且线 `status=done` |

#### ⚠️ 副作用：等待期从"18 个月"变成"等到他有新作"

三家公司的"有活"窗口（`companyInDevCatalogTitle` 口径，实测）：米哈游 **2012-09 起**、叠纸 **2013-01 起**、鹰角 **2017-05 起**。

而玩家收束后辈线的典型年份落在 **2000-2010**（开线门槛 = 入行 36 个月 + rank≥4 或 1 项署名，每年 34% 掷）。也就是说：

- 抽到**鹰角**、又收束得早 → 电话要等到 **2017 年**，游戏内 100+ 回合
- 抽到**米哈游 / 叠纸** → 最早也要 **2012 / 2013 年**
- 2011 年前收束的玩家，电话统一"多年后"才来

叙事上这是成立的（"某天的一个陌生又熟悉的电话"本来就是多年后），但玩家间隔很久。若要缩短，可调项：
① `bonds.juniorRevealPool` 只保留成立更早的公司；
② 把"对应的公司"改成等待期动态挑一家当期有活的；
③ 放宽为只判 `requireInDev`（不判成立年）。
