# 交付确认单（部署完成 + 预览二维码）

对应 PROCESS.md 的 deliver 阶段：部署与冒烟通过后发给开发者的**最终交付消息**。
只谈业务结果与可点击链接；环境、网关、manifest、脚本、验收、EnvId 等机制词一律禁止出现。

## 三条硬规则

1. **「线上地址」只能是真实部署验收通过的地址**：`activity.manifest.json` 里 `verification.ok=true` 且有 `publicBaseUrl`（HTTPSERVICE 网关域名，`*.app.tcloudbase.com`）时，才可以把该地址作为「线上地址（真实数据）」发给开发者。H5 页面线上地址只允许后台上传临时链接（`activity-static.hupu.com`）；**严禁使用 CloudBase 静态托管域名（`*.tcloudbaseapp.com`）作为线上地址或回传链接**。
2. **禁止把本地地址当在线预览**：`localhost`、`127.0.0.1`、`:8080` 等本地端口、`file://` 本地文件、未发布的静态预览地址，**一律不得**标成「在线预览（真实数据）」。本地文件只能以「本地文件位置」形式附在消息里（可点击 file 链接）。
3. **预览二维码先问后做**：生成虎扑扫码预览二维码是可选动作，询问就放在本确认单「可选下一步」里（不单独另发一轮消息）；未收到开发者确认前禁止运行二维码脚本（见 act-cloudbase 的 references/preview-qr.md 门禁）。
4. **禁止 CloudBase 静态托管部署 H5**：H5 线上/预览地址唯一来源是后台上传临时链接（`update-activity-html.js` → `activity-static.hupu.com`）；禁止 `manageHosting` / `tcb hosting deploy` / `*.tcloudbaseapp.com` 静态托管域名。

## 消息结构（按顺序）

1. **交付完成声明**：一句话，页面已完成部署并接入真实后台、正式可用。
2. **线上地址（若有）**：只有冒烟验收通过的 `publicBaseUrl` 才放；没有就省略，不编造、不拿本地地址顶替。
3. **本地文件位置**：`h5/index.html` 的可点击 file 链接（`[index.html](file://<绝对路径>)`），开发者可自行打开。
4. **交付内容对照**：与已确认方案一致的功能清单（如赛程/比分展示、焦点赛事、状态筛选、分享与统计），一句话即可。
5. **确认交付**：回复「确认」；要调整直接说。
6. **可选下一步**：询问是否需要——生成虎扑扫码预览二维码；或帮忙打开本地文件夹/预览文件。
   生成二维码前告知：预览链接为**临时链接，1 小时后失效**，仅供扫码看效果；真实文件在本地 `h5/index.html`，正式版需上传到后台。

## 模板

```text
**交付完成**
页面已完成部署并接入真实后台，正式可用。

**访问**
- 线上地址（真实数据）：<publicBaseUrl，仅当 verification.ok=true 时填>
- 本地文件：[index.html](file://<工作区绝对路径>/h5/index.html)

**交付内容**
<与已确认方案一致的功能清单，一句>

确认交付请回复「确认」；要调整直接说。

**可选下一步**
需要我帮你：
1. 生成虎扑扫码预览二维码？（临时链接 1 小时有效，仅扫码看效果）
2. 打开本地文件夹 / 预览文件？（真实文件在本地 h5/index.html）
回复「确认」和需要的选项即可；不需要也可以。
```

> 预览二维码生成的是**临时链接**，1 小时后后台自动清理、链接失效；**不代表上线**。正式对外可用以部署上传到后台的版本为准。

## 用词指导

| 对开发者说 | 不要写 |
|----------|--------|
| 页面已完成部署、正式可用 | 部署脚本、网关、环境 ID、`publicBaseUrl` |
| 线上地址：`https://...` | `localhost`、本地端口、`file://` 物理路径当在线地址 |
| 本地文件：[index.html](file://...) | 纯文字绝对路径 `/Users/...` |
| 生成虎扑扫码预览二维码 | `update-activity-html.js`、`live-preview`、Schema |

**禁止把任何本地/未发布地址标记为「在线预览（真实数据）」**；本地文件只能以「本地文件位置」形式出现。
