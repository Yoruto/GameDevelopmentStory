# 虚拟作口碑标尺：一次数值重定（2026-09-16）

## 目标（Master 给定）

| 队伍 | 熟练度 | 期望口碑 |
|---|---|---|
| 全属性 80（5 人队，6 个月，同题材+玩法） | 高（题材档 + 玩法档 = +40%） | **8 ～ 10** |
| 全属性 30（5 人队，6 个月） | 无（0%） | **≈ 3** |

## 为什么不是「把老除数 10 改成 6」

`口碑 = 四维均值 / D` 是过原点的一条直线，两端比值被锁死：

- 实际四维均值比 `liveMean(全80高) / liveMean(全30无) = 60.7 / 16.3 = 3.72`
- 目标分比 `9 / 3 = 3.0`

直线过原点时两个比值必须相等 → 无解。取 `D=5.43` 能命中 3.0 但全80高变成 11.2（爆表）；取 `D=6.5` 能把全80高压到 9.3 但全30无掉到 2.5。
**必须给这条换算线一个「保底基准分」**，让强队段有压缩、弱队段有托底。

## 落地方案

```
虚拟作口碑 = craft.scoreBase(1) + 四维均值 / craft.statDivisor(7.5)   然后夹 scoreFromLive.min～max（1～10）
```

- 立项时读**立项四维均值**（写入 `title.score`），发售时读**当时的 live 四维均值**。
- 人数与工期**不再**在口碑里重复计算：人数已经折进立项四维（`virtualPool.teamStatShare` 10% × 人数求和），工期靠每月贡献抬 live。
  旧的 `craft.refTeamSize / refMonths / sizeExp / timeExp` 已删除。
- 目录作（含 landmark）**完全不受影响**，仍走 `scoreFromLive.divisor = 10` 与表内 `score` 的混合。

两个旋钮：

| 参数 | 现值 | 作用 |
|---|---|---|
| `virtualPool.craft.scoreBase` | 1 | 保底分。调高 → 全曲线整体上移，弱队被托得更多 |
| `virtualPool.craft.statDivisor` | 7.5 | 斜率。调小 → 分差拉大，强队更吃属性、弱队更低 |
