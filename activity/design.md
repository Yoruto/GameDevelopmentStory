# 游戏开发物语 · 设计（对齐现行 sim）

本文描述**已经落地**的玩法，不是待做草案。可点页面在 `h5/index.html`；规则在 `h5/js/sim/`；目录与接口见 `activity/architecture.md`。

sim 只有一套局：**生涯档**（`mode=career`）。玩家是 1995 年入行的职员，一路做到 2025——不当社长、不招人、不立项、不经营公司（原经营局逻辑已于 2026-09 整体移除，代码与文档均不再保留）。

## 1. 生涯档怎么走（1995–2025）

玩家是刚毕业入行的职员，不是社长。先写**角色名**（默认文案「阿喵」），再锁一个擅长岗（程序 / 策划 / 美术 / 音乐；制作人岗本版不可选），再从三份开局 offer 里入职：小作坊、稳定岗位、野牌各抽一家（`openingOffer.tiers`）。档内按 `weightByPower` 抽（现 `{1:4, 2:2, 3:0.25}`），小厂权重大、大厂很少开局出现——`power3` 只在「稳定岗位」档有候选（史克威尔 / 卡普空 2 家），压权重后单份约 0.46%、三份里至少出现一次约 1.4%（改前 1.84% / 5.53%）。把 `weightByPower["3"]` 设为 0 可让大厂彻底不进开局池——这与「大厂要职级 3 才收人」的门槛是同一套逻辑，新人本来就进不去。岗位按擅长锁定，薪资按档位表取整。入职后 `phase` 从 `OFFER` 变成 `PLAYING`。

时间要点「下一月」。玩家**不能**招人、换场地、广告、立项、发布——这些经营行为没有实现，也没有入口。能做的是：看自己所在组的在研、每月贡献主职维、处理开发/热修抉择、年底申请跳槽、被挖时接或留下。关掉再打开自动接着玩。结算不分享。

- **在研**：优先挂到本公司本工作室、当前年月正在开发的目录作品（`careerWorld.titles` + `titleDetails`）。空窗到下一档目录真作不足 `idleGap.minDevMonths` 时不开虚拟作，弹出一次空窗抉择（借调 / 学领域外 / 精进），整段空窗只结算一次。空窗够长则待命超过 `idleMaxMonths` 后从 `virtualPool.titlesByGenre` 抽虚构作，工期 6～min(24, 空窗可用月数)，发售不压过下一档真作开工；不要抢同公司同月 landmark 档期。组里是 5 人：制作人 + 四职，玩家占锁定岗，其余复用本公司同事池。同事四维和 `jobRank` 按东家 `power` 抽（`colleagues.byPower`），不克隆当前作品 `title.stats`。目录作同事只解释品质、不把 NPC 月贡献叠进 catalog 四维；虚拟作立项才把玩家+同事按 `virtualPool.teamStatShare` 一起计进四维。**长线标记作品**（`releaseType=liveops` / `liveAfterRelease`）发售后**当月卸下**——没有「留在组里做版本」这回事；系列新版本是目录**重新立项的一部新作品**（见第 3 节）。
- **开局与影响力**：开局各维在十几到二十出头，擅长维再加 `specialtyBonus`，主职仍落在 20 出头。职员月贡献四维都加：每维 = 基础 × 职级倍率 × `careerStatFactor(该维属性)` ×（主职 `contribMainMult` 1.15 / 其余 `contribOffMult` 0.4）× **阶段权重 × 体量权重** × 玩家熟练度倍率。`careerStatFactor` 是属性软上限（`quality.statSoftCap`：`max × stat/(stat+ref)`，ref=100 / max=2）——属性本身**无上限**，但产出倍率收敛到 2.0×，200 只给 1.33×。阶段权重 `development.phaseMult` 按项目所处阶段缩放（立项 0.6 / 制作 1 / 填充 1.2 / 打磨 1.5 / 金盘 0），体量权重 `development.powerContribMult` 按发行体量缩放（小体量 1.25 / 中 1 / 大体量 0.8）：同一个人在 5 人小品里顶半边天，在 3A 里只是螺丝钉。玩家熟练度倍率 = 1 + 题材/玩法各自档位加成之和（0% / 8% / 17% / 30%，见 `proficiency`），四维共用；制作人同样吃这个倍率。对外口碑玩家权重、玩家抉择的 `qualityDelta` 仍乘职级倍率再乘 `careerStatFactor(主职维)`。目录 landmark 上绑了 `titleId` 的史实通知不缩放。
- **两套口碑**：目录作（尤其 landmark）以表内 `score` 为主，加杰作加成和很小的玩家混合，并有 landmark 保底，实习生带不动塞尔达。虚拟作走 `virtualPool.craft` 自己的标尺：口碑 = `scoreBase`(1) + 四维均值 ÷ `statDivisor`(7.5)，夹 1～10；立项读立项四维均值，发售读当时 live 四维均值，不走媒体 divisor。锚点：全 30 队无熟练立项 3.0；全 80 队无熟练 6.3、高熟练(+60%) 9.5、开发 6 月后 9.1；两年以上的顶级队才够 10。发售媒体分围着对外口碑抖动。
- **立项初始四维**：虚拟作立项时四维 = 全员（玩家 + 同事）各维先按 `virtualPool.teamStatShare`（10%）求和再向下取整，然后乘工作室熟练度加成。5 人小队出的是「队伍均值的一半」，不是均值本身。工作室熟练度加成看 `studioXp` 的题材档 + 玩法档，两档相加：生疏 0% / 熟练 8% / 拿手 17% / 看家本领 30%（`proficiency.ladder`），两条线都练满最高 +60%。没有工作室时退回公司经验桶。玩家个人熟练度**不**参与立项，只进每月贡献。
- **每月**：在研时给作品四维加月贡献（主职维更高、其余维按该维属性加较低倍率；制作人四维全加成不变），并给 `career.stats` 主职维和 `jobXp` 加点——三者同乘当月成长倍率（阶段权重 × 体量权重），玩家才对得上「这个月干了多少活」：立项期慢慢磨、填充与打磨期进步最快、金盘期只等压盘（0，连职级经验一起停）。可出随机开发事件（通知或抉择，按 `minRank`/`maxRank` 过滤，负向事件低职级更常见）。随机事件大约每 4 个月一条（`devEvents.chance` / `minGapMonths` / `pityMonths`，每年最多 `maxPerYear` 条，大约一年 3–5 条）；当月若已出事件线拍子则不掷随机池。目录作发售当月结算口碑、媒体、奖项、署名履历，当月结束后卸下当前作，进入空窗/下一作/短空窗抉择，不再占用 1～3 个月后续支持。跳槽已不署名则发售也不署名。制作后期加入（`lateJoin.progressMin`）记参与但不署名。**属性成长速度锚点**（2026-09-18 削弱 35% 后实测，开局主维约 24 的同一局）：10 年 40、20 年 59、30 年 75、34 年 81（削弱前同点是 48.6 / 77.5 / 101.6 / 111.7）。三档基础值在 `jobRanks.statGain`，要回调整体速度按同比例改 `perDevMonth` / `perRelease` / `perPostLaunchMonth`。**升职 `mainStat` 门槛与这条曲线是同一把尺子**，改速度必须同步改门槛（现 28/34/41/51/60，按「开局主维约 24 起算的增量」标定），否则高级职级会变得不可达。
- **钱与声望**：月薪入积蓄；本版 `deductLivingCost=false`。声望/荣誉跟履历和奖项走，不是公司粉丝。薪资每年按技术/声望/职级/通胀重算后夹到档位，且不得低于该职级 `salaryFloor`，禁止零头。
- **两套熟练度**：工作室 `studioXp` 决定虚拟作立项初始四维加成（题材档 + 玩法档相加，见 `proficiency`），目录真作（非玩家立项）仍按 `companyXp.statBonusPerXp` 平加。玩家 `genreXp` / `gameplayXp` 只乘在每月贡献上，不再抬 live 四维底。开局从全表随机两个题材、两个玩法达到「熟练」（XP 见 `playerXp.startingAbleXp`）。公司历史作会预种工作室 XP。开发月、发售、空窗精进、开发事件（品类课 / 试玩笔记 / 对标表等）都可加玩家 XP。题材/玩法熟练度是品类熟不熟，不和职级抢「我是谁」。总览可进玩家详情看全部档位，不展示具体经验值。
- **职级**：`roleId` 开局锁定不换轨（制作人是唯一例外，见下）。`jobRank` 1–6 是成长的脸（程序：代码实习生→技术总监；策划：策划实习生→策划总监；美术：美术实习生→美术总监；音乐：音频实习生→音频总监）。展示用职级代号挂在同一条梯子上，不另开一套：程序 T、策划 D、美术 A、音乐 M；称号里的 `code` 是 实习生 0 / 初级 1 / 中级 2 / 高级 3 / 主职或专家 4 / 总监 5。界面写成 `初级美术 (A-1)`。1995 开局固定 Lv.1（T/D/A/M-0）。职级与主职维一起调制月贡献、对外口碑权重（`jobRanks.contribMult` 0.6→1.2，每级等步长 0.12，整段跨度 2x，刻意平缓：职级是成长的脸，不是数值放大器）；跳槽通过率看职级和对口熟练度。大厂 offer 可要求 `minRank`。
- **前辈与人物线**：每家 `joinable` 公司在 `career-world.json` 的 `seniors` 里至少挂一名具名前辈（id / name / title / bio / tags）。入职钉 `career.bonds.mentor`（该公司 seniors），可钉 0–1 `peer`（同事池，跳槽保留、不改名）；后辈线会生成早期昵称「小T」的 junior，回国线再对上表内前辈 alias。开局 offer、职员总览与挖人仍亮东家前辈名。可选事件线（前辈/同事/后辈/史诗作/回国）与职业轨（晋升 4→5/5→6、成为制作人）**不是互斥组**：一局运气好可以五条都走完，差也可以只开到 1 条；用 `startWhen` 权重/门闩控制，不要用 `exclusiveGroup` 禁止五条。职业轨仍走 `exclusiveGroup: careerPath`。多条线可同时 `active`，每月默认最多 1 拍（`eventLines.maxBeatsPerMonth`），按 `priority` 选拍，避免关系线吞掉晋升/制作人。人物线按主题展开：前辈线（成长，take-in → 工位课 → 自己的声音 → 独扛 → 提名；职级 1–2 故事晋升 +1，职级 ≥3 可由前辈破例开 `become-producer` 但不降低全局 minRank 4；已是制作人则只给体面）→ 若前辈有 `successorCompanyId` 再问跟走；同事线（竞争，需职级 ≥3）终局多结局互斥；后辈线（传承，职级 ≥4 或已有署名作）终局留组/推荐/成全或拦，真名仍只在回国线 `revealJunior`。跳槽保留已钉对象并刷新 `colocated`；`monthsTogether` 只在同公司（或合并后继任东家）时累加。同线中途分开则插入「还联系吗」，不断线则后续拍用远程文案。故事晋升计入 `promotionsThisYear`，跳过点击门槛；同年已升过则推迟到次年 1 月。前辈出走（如小岛秀夫 科乐美 → 小岛组）可选择跟随到 `successorCompanyId`，不跟随是合法结束。
- **晋升**：达标（主职能力必须够，另加主职维或 jobXp、署名作品权重、声望或荣誉、任现职满 N 月）只是可晋升。能力不够不能点升、也不能开晋升事件线。故事/事件线效果晋升（`applyCareerPromotion` story）可跳过这些门槛。1→2 / 2→3 / 3→4 仍可点一次即升；4→5（高级→专家）与 5→6 走多拍晋升事件线，升职在最后一拍生效。发售当月、年底 offer、总部按钮都可开线。一年最多升 1 级，跳槽带着职级走。本版不降级。拒绝/中断则职级不变，若仍达标可于次年重开。
- **履历**：`tenures` 记任职时间线；`credits` 记参与作品（当时职级、加入/离开、是否署名发售、是否虚拟作；发售时写出口碑、主职维贡献、该作奖项）。制作后期加入的作记参与但不署名。履历页只展示署名作品。
- **跳槽/邀约的准入**：offer 与挖人只发给"当年月真有在研目录作"的公司（`mobility.requireInDevTitle`，默认全开；可整体关或按 offer/invite/scripted/studioMove 分面关）。判据是 `sim.companyInDevCatalogTitle`——目录作才算，虚拟作不算（虚拟作本身就是空窗的产物）。没有在研作的公司不进 offer 抽签池、不进挖人候选；剧情邀约（同事线跳去别家/搭史诗作、前辈线跟着走）与内部调岗的落点不成立就不开选项或先不拍那一拍，效果层兜底是"原地不动"。理由：企业挖人是为了让人做事情，被挂进空窗公司过月就会被塞一部虚拟作。开局 offer（应聘入职）不受此约束——1995.1 只有 11 家有在研目录作，收紧会挤掉"小厂开局 + 自家立项"。
- **跳槽**：每年 12 月给出最多 4 格 hop offer（`mobility.offerCount`），内部工作室调动最多 2 格且排在前面；可晋升时内部晋升占用其中一格（高级及以上为开事件线而非当场升职）。跳槽页只展示公司、小组（若有）、新薪、职级与成功概率，概率靠右；不展示前辈与是否对口，也不对照当前薪资。点公司行即可申请（点到行内文字也算）。一次只能申请一家，并通过率掷骰；失败记 `hopFailedYear`，本年不能再投。**通过率公式**（`sim.careerHireChance`）= `company.hireChance`（power 级基准，现 1→0.72 / 2→0.48 / 3→0.14~0.32）+ 声望 ×`fameHirePer` + (主职维 − `salary.statRef`) ×`statHirePer` + 职级加成 `hireChanceRankBonus` + 对口熟练度档（`skillHire.bonusByTier`），整条再 ×`hireChancePowerMul[power]` 后夹 `hireChanceMin`~`hireChanceMax`；大厂另有职级硬门槛 `offerMinRankByPower`（现 `{1:1, 2:1, 3:3}`）——职级不够时大厂 `chance` 被硬置 0，而**这种 0% 的 offer 不进跳槽表**（`makeHopOffer` 返回 null）：选项位很稀缺（4 格），排一排点不进的公司既挤位又误导。职级够了以后大厂照常按低概率回归（实测 Lv.4 时 4%~30%）。⚠️ **`hireChanceByPower` 是死配置**——128 家公司全部显式写了 `hireChance`，它永远被覆盖，调它无效；要削弱进大厂请改 `hireChancePowerMul`（现大厂 0.62；声望斜率 `fameHirePer` 已从 0.004 砍到 0.002）。实测削弱后大厂通过率：中期 20% / 后期 34% / 顶级 54%（原 35% / 63% / 顶格 92%）。年底 offer 与挖人抽公司也会按对口加权。本版允许开发中途跳槽；发售当月和短空窗中也可以跳。年中挖人（invite）必成：接受则跳槽（可带更高职级），留下则清空邀请，不再对原公司讨价还价（`mobility.inviteCanCounter=false`）。制作后期项目默认不进挖人池；跳槽若挂到后期作，通过率乘 `lateJoin.hopHireChanceMul`，加入也不署名。挖人/跳槽岗不绑死当前 `roleId`：按 `mobility.inviteRoleWeights` / `hopRoleWeights` 抽职员四岗；**制作人岗**仅在 `become-producer` 事件线 `status=done` 后才可能出现在常规挖人池（回国线等剧情 invite 可单独允许制作人岗）。接非制作人 offer 时 `roleId`/`growthStage` 切回职员岗。被踢出当前公司后 `companyId` 为空，走同一套年底 offer / 挖人 / 空窗求职，不另扣钱、不改世界销量。
- **制作人**：`jobRank >= 4`（高级及以上）可开「成为制作人」事件线（与晋升线互斥）。一局最多询问 2 次（`maxAsks`，含职业分叉与 invite 拍）；满次后不再问。前辈提名可在职级 3 破例开同一条线，不降低全局门槛，但仍计入询问次数。完成后 `roleId=producer`、`growthStage=producer`，保留原 `jobRank` 供履历；展示职称改为制作人。仍是现公司员工，不招人、不换场地、不动公司资金、不开公司。**仅虚拟作**可选题材/玩法（producer pitch）；目录 landmark 禁止玩家改名或改写题材/玩法（定调风味事件可以）。制作人有独立事件池与四维月贡献。
- **成长**：`growthStages.founder` 本版锁定（`lockedThisVersion`）。可经事件线成为制作人，但不能自己开公司。升到 Lv.6 只是专精头衔和薪资天花板，不解锁招人/立项。
- **天赋**：开局从 `config.traits` 的 career 池按 `drawWeight` 抽 `startRoll.traitCountMin ~ traitCountMax` 条（当前 **1~3 条随机**，与入行熟练度和属性同一掷一起出），且**同「收益轴」最多一条**（`traits[].axis`：out/growth/skill/event/bond/insp）——抽到即全部生效、不可改、界面上没有选择步骤。天赋天生，之后不加新、不改旧；效果数字只在配置。
- **世界发售**：点月按目录把本月该出的作品写入 `worldReleased`（含长线标记与峰值）。目录作四维进局时先按 `quality.eraStatScale` 乘发售年倍率（前期底低、后期底高），再相对缩放后的基准按整数百分比浮动（`quality.statJitterMinPct`～`statJitterMaxPct`），向上取整；虚拟作 live 按立项四维（全员 10% 相加 + 工作室熟练度加成）起底，随开发月贡献成长。标志性系列的新版本已按 `liveTag` 规则预填目录（每个日历年每系列 ≤1 部，命名「系列：版本名」），日历用 `careerYearReleases`。
- **评奖**：每年 11 月过月。提名门槛取「绝对线」与「当年池中位数×相对线」的**严格值**，前二接近才摇号（细则与评分子见 §4 年度奖）。盒装奖看窗口内已发售目录作；最佳长线看**颁奖窗口内发售**的长线标记作品（不跨年、不看「仍在运营」），按四维合计（`scoreFrom: qsum`，缺四维用销量兜底）比较。读 `worldReleased` 上的 stats / score / releaseType（即浮动后的局内四维），不读空的 `titleDetails.awards`。情报里的年度奖页顶栏年份从早到晚横排，可左右滑（后期也能滑回 1995）；点年份只看那一届，打开时对准当前选中年。
- **终点**：推进到 2025 年 12 月结束后 `SETTLED`。结算看角色名、职称、声望、荣誉、署名作数、积蓄、最后东家。没有公司破产线。

点月之前，生涯档玩家可以做这些操作（不会自己发生）：

1. 要不要申请年底 offer / 内部调动 / 内部晋升（高级及以上开事件线）。
2. 达标后要不要开晋升（低职级当场升；高级及以上走事件线；一年最多一次）。
3. 高级及以上要不要走「成为制作人」事件线（与晋升线互斥；一局最多询问 2 次）。
4. 被挖时要不要跳槽或留下。
5. 开发、空窗或事件线抉择（过月 queue 里点选项；人物线/史诗作/回国线也走这里）。
6. 点「下一月」。

禁止自动过月。目录作与虚拟作的发售日由规则表推进。

## 2. 两套四维与质量换算

**两套四维是分开的，靠一张系数矩阵换算。**

- **人物维**（玩家自己的属性）：**程序、策划、美术、音乐**，键 `program` / `design` / `art` / `music`（员工数据里策划写作 `script`，`sim.personStatVal` 统一收口）。维度表在 `careerWorld.quality.personDims`，展示名读 `copy.career.dimProgram/dimDesign/dimArt/dimMusic`。只出现在：开局选岗、HQ 自身四维、`roles[].stat`、`jobRanks`、`career.stats`、`inviteRoles`、`seniors[].tags`。**永远不要拿作品维去索引人物。**
- **作品维**（作品自身的质量）：**游戏性、趣味性、表现力、沉浸感**，键 `play` / `fun` / `expression` / `immersion`。维度表在 `careerWorld.quality.dims`，展示名读 `copy.career.prodDim`。只出现在：`titles[].stats`、`peakDims`、`devEvents`/`postLaunch` 的 `qualityDim`、`career.liveStats`、`worldReleased[].stats`、媒体权重、`awards[].stat`。**永远不要拿人物维去索引作品。**

两套之间的唯一换算层是 **`careerWorld.quality.personToTitle` 系数矩阵**，纯配置、调平衡不用改代码。要让「程序」同时抬游戏性和表现力，就给 `program` 一行写 `{ "play": 0.7, "expression": 0.3 }`。系数只是乘法；不改平衡时应保持每行合计为 1，否则作品四维总量会整体放大或缩小。

代码侧的换算入口只有一个，别另写一套：`sim.titleStatsFromPerson(personStats, config, mult, matrixOverride)`。月贡献、虚拟作底分都走它。

原本的「策划 / 美术 / 程序」三项合计、「制作人权重 2、成员 1」的旧口径，以及制作人专属矩阵（`producerToTitle`）都已随经营局移除或废弃。

## 3. 已发售作品、长线标记、系列

发售之后，目录作/虚拟作从在研变成作品记录：题材、玩法、发售年月、四维、口碑、媒体分。

### 销量口径

- **基准与首发**：发售结算用 `careerWorld.launchSales` 公式算基准（`sim.careerLaunchSales` = `baseUnit × e^(k×(score−scoreRef)) × prestigeMult × qualityMult × powerMult`，对评分超线性——9.9 分与 8.6 分能差一个数量级，百万级爆款与长尾小作拉得开）。**斜率 k 在 `scoreRef`(7) 处换挡**：及格线以上用 `scoreExp`（每分 ×5.5），及格线以下换更缓的 `scoreExpBelow`——纯指数的下尾会把 3 分作品压到个位数（e^−6.8 ≈ 0.001），可真实市场里再烂的作品也有基础曝光（3 分小厂作 ≈ 665/首月）。换挡只抬下尾，7 分及以上完全由 `scoreExp` 决定、一个数不动。`sim.salesFactor`（Y 曲线首月系数）与 `sim.boxedActualFromY` 得出发售当月实销，盖章到 `rec.baselineSales` / `rec.launchSales`（`lifetimeSales` / `monthSales` 初值 = 首发实销）。**长线标记作品和盒装走同一条生命周期**，一样盖这两个字段。
- **Y 曲线**：指数衰减，参数只读配置 `lifecycle`：`lambda0` `lambdaSpan` `tMin` `tSpan` `scoreMin` `scoreMax` `maxMonths`。令 x = m−1，u = (S−scoreMin)/(scoreMax−scoreMin) 夹在 0～1，λ = `lambda0` + u×`lambdaSpan`（`lambdaSpan` 为负 → 高分衰减更慢），T = `tMin` + u×`tSpan`，则 Y = T + (1−T)·e^(−λx)。实现认公式，不算查表。首月之后每月实销 = 基准 × Y(m)。
- **只显示月销量**：揭晓面板的销量行只有一个「月销量」= `rec.launchSales`（发售当月实销）。原来切出来的「首周销量」（`week1Share` + `sim.boxedWeek1Units`）已于 2026-09-18 随需求删除，配置项 `lifecycle.week1ShareMin/week1ShareSpan`、文案 `copy.week1SalesLabel` 一并清掉，别再按它写文案。

### 本月榜单

生涯档榜单 = **本月 `worldReleased`（世界发售）按当月实销排序**（`sim.monthlyChart`）。没有假游戏占席、没有掉榜停售——生涯档不做「玩家作品和假游戏抢席位」那套经营局机制。

### 长线标记

「长线运营」只是目录上的一个标记（`releaseType="liveops"` / `liveAfterRelease`），没有独立运行逻辑：发售后当月卸下制作组、销量口径与盒装一致、没有维护占编/月收/关服。

| 规则 | 说明 |
|------|------|
| 版本拆分 | 系列新版本 = 目录**重新立项**的一部新作品，显示名按 `liveTag.labelPattern`（`{series}：{versionName}`，如「原神：空月之歌」）。没有自动推进的版本号（1.0/2.0 已废） |
| 闸门 | `liveTag.versionsPerYear = 1`：同一系列每个日历年最多发售 1 部（首发也占这一格）；`liveTag.minIntervalMonths = 12`：同系列两次发售最小间隔。目录生成时就截住，不靠 UI 藏 |
| 数据范围 | 只有**标志性系列**（原神 / 魔兽世界 / LOL / 王者荣耀 / 明日方舟 / 星穹铁道 / 绝区零 / 鸣潮 / 崩坏3 / 梦幻西游 / DNF / 剑网3 / 炉石 / 守望先锋 / PUBG / 永劫无间 / 我的世界 / Dota / 暗黑破坏神 / 堡垒之夜）按年度预填版本条目（`career-world.json` 里带 `versionOf`）；其余长线作品保持单条 |
| 版本名 | 不填版本名时用 `liveTag.defaultVersionName`（「新章」）。版本号只作副标签展示（`liveTag` copy），不参与命名 |

### 系列续作

这是「一个系列」，不是单个作品的剧情续作。像马里奥 2 / 3、GTA：故事无强制关联，不用先玩 4 再玩 5。系列名永远是首作名，新版本只追加作品；系列声望取最高。

## 4. 潮流、媒体、年度奖

### 题材热点潮流

随机刷新（间隔、持续见配置）。发售时，题材或玩法对上当月潮流的作品吃销量加成（`sim.matchesTrend`：题材或玩法任一对上即算）。事件可以把潮流改成指定题材或玩法；总览写「玩家开始喜欢 xx」。

### 游戏媒体评分

目录作发售走目录月，媒体/奖项进过月 queue：

- **4 家媒体**各打一份分；对外第一版用化名（名单见配置），不要把真名写成必须上线的设定。
- **均分 = 四家分数取算术平均**，这就是玩法面板上那个「均分」，也**就是这件作品的对外评分**：`media.avg` 是唯一来源，`sim/career.js` 的 `shipPlayerTitle` 把它写回 `rec.score` / `rec.avg`，榜单 / 奖项 / 销量曲线 / 履历 / 情报条全读这一个数。禁止把「对外口碑」直接当均分显示（2026-09-18 的 bug：口碑夹到 10、四家被 min/max 夹成 9.6~9.9，面板却写「均分 10」——玩家拿四行手算一下就能发现对不上）。
- 四家怎么从四维收成分数：生涯档走 `sim.scoreMediaFromPublic`，**围绕对外口碑（`sim.liveToPublicScore`）抖动**：正负各半（两家偏高、两家偏低，哪两家随机轮换）→ 两侧配平（均分恒等于口碑）→ 按到 `minScore`/`maxScore` 的余量整体收窄（永远不被夹）。系数与化名名单见配置。
- 面板下方有一段随机媒体人点评。评语按媒体自己的口气池抽，档位由该媒体自己的分数切，写在 `copy.mediaQuotePools.outlets`。
- **档位**：`release.media` 的 `topScore`(9.5) / `highScore`(8) / `lowScore`(5) 把 1–10 切成 top / high / mid / low 四档（`sim/media.js` 的 `quoteBand`）。顶级档是给满分作留梯度的：10 分作品不该拿到「值得一买」。某档缺条目时按就近回退（顶级→高分、低分→中分，见 `bandList`），不要退回 `||` 链，否则补了 top 池却掉到中评。
- **四家媒体各是一个人，刚好各占作品四维之一**，只谈自己那一摊，池子可以串味就是文案 bug：IGM 只谈手感/判定/难度/平衡（游戏性 .35）、机刻 只谈故事/人物/巧思/趣味（趣味性 .40）、游民星宫 只谈画面/美术/镜头/界面（表现力 .40）、触悦 只谈感受/氛围/世界感（沉浸感 .35）。原来的第 5 家「发米通」（四维均衡）已删除——它的口径与 `overall` 池重复，删掉后四家与四维一一对应。
- **写评语的硬约束**：一句话、2~18 字、只允许「，」「。」「！」「？」「…」；不带机构名（界面自己渲染）；每档 24 条（top 8 条），按角度分组补，别把同一句换个说法塞两遍；**口语文案**——写成像玩家在论坛/短评里随口说的话，允许网络用语（神作 / 拉完了 / 上头 / 封神 / 劝退 / 绝了 这类），不要写成行业口径或媒体腔。⚠️ 本池**已不再强制 1995~2025 时代安全**（用户明确要网络用语）；若要按年代收敛，得另加年份闸门，不要靠禁用词硬删。改完 `python scripts/sync_config.py`，再跑 `python .workbuddy/tmp/check-media-quotes.py` 自检；`copy.mediaQuotes` 只作最后的兜底。

### 年度奖（TGA 味）

**每年 11 月过月时触发**（生涯档走 `runCareerAwards`，自包含）。

- **盒装奖**（年度游戏、最佳玩法/叙事/视觉/配乐、玩家之选）：参选 = **去年 12 月～今年 11 月** 窗口内已发售目录作。
- **最佳长线运营**：只收**颁奖窗口内发售**的长线标记作品（`releaseType=liveops` / `live` / `liveAfterRelease`），**不跨年**、不看「仍在运营」（没有这个概念）。按四维合计比（`scoreFrom: qsum`；候选缺四维时用销量兜底 `fallback: sales`）。读 `titles[].releaseType`，不要只读 `titleDetails.liveAfterRelease`。
- 长线标记作品与盒装一样可进各奖项窗口（发售后不再有「运营中」的单独池子）。
- 奖杯抬声望与角色荣誉，不直接发真实奖品、不涉及钱。玩家之选读的是 `launchSales`（发售当月实销），不是 lifetime。
- **评分子与门槛**（`awards.score`）：每个候选先算综合评分子 = 口碑（`score×10` 归一）×w₁ + 质量（四维均值归一）×w₂ + 商业（销量取对数归一）×w₃，权重按奖项分三套：年度游戏 0.5/0.3/0.2、玩家之选 0.15/0.25/0.6（重商业）、其余 0.2/0.8/0。奖项带 `scoreFrom` 专属口径时，用 `categoryWeight` 把它与综合分混起来；`qsum` 口径直接用四维合计，不混。
  - **提名门槛取严**：`gate = max(absolute, 当年候选池中位数 × medianMul)`。绝对线与相对线谁高听谁的；候选凑不齐 2 个时保底取全池。⚠️ 标定门槛要看**运行态**分布：目录作进局时四维会过 `quality.eraStatScale` 的时代缩放（1997 只有 0.62×、2025 才 1.08×），拿 json 原值估会高估一大截。
  - **评审抖动**：前两名分差 ≤ `jurySuppressGap` 才摇号（±`juryJitter`），差距大则强者稳定胜出——避免「分高者莫名落选」。
  - **重复获奖衰减**：同一奖项第 N 次拿到，名气收益乘 `(1+prior)^(−repeatFameDecay)`，防止同系列连年刷同一座奖杯。
- **揭晓（UI）**：媒体评分先出评语，再在评语后显示分数，一家一家从上到下。颁奖夜一条一项，滚提名后揭晓获奖作，不盖斜印章。玩家参与制作的获奖作用不同颜色标出。`ceremonyLast`（年度游戏）压轴。滚幕时长只按奖项大小分两档、与出场顺序无关：小奖项 1 秒、大奖（年度游戏）2 秒；点屏幕可立刻开奖。时长只改配置 `fx`（媒体四家合计约 1.6 秒）。情报里的年度奖页可上下滑看当届名单；顶栏年份钮从早到晚横排、可左右滑，点年份只渲染那一届，玩家作品同样高亮。

## 5. 点月时结算顺序

`sim.tickMonth` 就是 `sim.tickCareerMonth` 的直接委托（经营局分支已删）。

1. 补齐存档缺字段；没有工作室 id 则落到该公司默认工作室。
2. **在研中**：四维加月贡献（主职维倍率更高；制作人四维均摊全加成），给玩家 XP 与主职维/`jobXp`——三者同乘当月成长倍率（阶段权重 × 体量权重，金盘期为 0），掷开发事件（按职级过滤；品类课等事件可加当前作题材/玩法熟练度）。随机池受 `minGapMonths`/`pityMonths`/`maxPerYear` 约束；当月已出事件线则跳过随机池。待命则跳过产出。
3. **世界发售**：本月目录作写入 `worldReleased`（标志性系列的年度版本已在目录里，按发售日正常进）。
4. 若玩家仍在组的作品本月发售 → 结算署名（后期加入则不署名）、口碑、媒体/奖项入队；达标则可入队晋升抉择。当月结束后卸下，不进后续支持占用。
5. **事件线**（`processCareerLines`）：每月最多 1 拍。东家 `hireUntilYear` 已过且有 `successorId` 时先入队合并抉择（跟着去继任公司 / 离开）。人物线因跳槽变成远程则先入队「还联系吗」。1 月开头结算上年推迟的故事晋升（`pendingStoryPromos`）。当月已出线拍则跳过随机开发事件。
6. **发薪**：月薪入积蓄；配置要求时再扣生活费。把积蓄镜像到 `company.funds` 仅供 UI 复用，不走破产。任现职月数 +1（仍在职时）。`tickCareerBonds` 只在 `colocated` 时累加 `monthsTogether`。
7. **若本月是 11 月**：生涯 TGA（盒装窗口 vs 窗口内发售的长线标记作品，最佳长线按四维合计）；有署名才把奖项写入该作履历。
8. 年中挖人：**按年掷一次骰**——`mobility.inviteChance` 就是「这一年会不会有厂商来挖」的概率（现 0.35），命中后最多给 `inviteMaxPerYear`=1 条邀请（可带更高职级；后期作默认不邀请）；候选还要求目标公司当月有在研目录作，所以实际收到的年份更少（实测 ≈25%）。选项只有加入或留下，不对原公司还价。⚠️ 旧实现是每月独立掷一次、失败不消耗次数，12 次叠加后年内命中率 ≈99.8%，等于每年必被挖一次——而挖人必成，那让「进大厂」变成零门槛。改语义时 `career.inviteYearHit` 是年度骰结果，与 `inviteYearStamp` 同年内不可重掷。
9. **12 月**：生成年底 offer 表（可含内部晋升格）；入队跳槽页（发售当月与短空窗也可跳）。点公司行即可申请；若挖人已加入且 offer 表被清空，UI 不再弹出空的跳槽页。
10. **日历 +1**；若刚进入新年：按新年重算月薪档，清空本年晋升计数。空窗累计后 `assignCareerProject`（目录、短空窗一次抉择或虚拟作），刷新同事。
11. 已过 `careerWorld.timeline` 结束年月 → `SETTLED`。

`tickCareerToDecision`：在仍为 `PLAYING` 时反复调用本管线，直到 `careerQueueNeedsDecision` 为真、终局、或达到 `careerPace.maxSkipMonths`。跳过至少 `summaryMinSkipped` 个月时，queue 前置一条 `paceSkip` 摘要。随机开发 notice、与己无关的颁奖夜可跳过；抉择、挖人、跳槽、事件线拍、署名发售 media、与己有关的颁奖会停下。
