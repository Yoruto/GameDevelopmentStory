# 整体思考（项目哲学与引导原则）

本文件回答「这个项目是什么、为什么这么引导、遵循什么原则」。它是 SKILL.md 背后「为什么」的解释层，不承载可执行步骤；可执行步骤在 PROCESS.md / references/ 里。

## 一、项目本质

这是一个**低代码活动生成 + 部署检查**的端到端交付项目，由三件套组成：

| 组成 | 是什么 | 在仓库哪里 |
|------|--------|-----------|
| 引导层 | 状态机（阶段链）+ 意图引导（先写草案再问，一轮问完整前沿） | PROCESS.md / state.py / references/requirements.md |
| 能力层 | ColorboxAI 前端能力技能市场（window.ColorboxAI 各 API） | skills/colorbox-skill/ |
| 交付层 | 每个活动的产物（需求单 / H5 / 迁移 / 云函数 / 测试报告 / manifest） | activity/ |

- 引导层负责「把开发者的真实意图问出来」；
- 能力层负责「被选中的意图用什么能力实现」（Agent 内部决策，不打扰开发者）；
- 交付层负责「每一步留下可检查的产物」。

三层各管一件事，互不越权：引导层不实现功能，能力层不做流程决策，交付层承载结果。

## 二、云服务是可选能力，按技能包决定问不问

- 云服务（act-cloudbase）是用户可选技能：选中才进技能包（`skills/act-cloudbase/` 存在），没选就没有云部署能力。
- **技能包含云服务能力 → 部署决策必须经开发者确认，且时序靠后**：无论业务看起来多「显然纯静态」（如个人专属卡、不记录、不限次），都禁止按推导预填落定；需求轮只问雏形（部署节点标 `deferred`），存储方式确认放到**静态预览获得开发者确认后、进入技术方案设计前**——**引导式选择**：讲清「云端保存 vs 本地保存」的区别并按业务给推荐（需要跨用户共享/持久/限次/排行 → 推荐云端；纯个人自嗨、数据可丢 → 推荐本地），禁止甩「要不要存」这种用户无法判断的抽象问题；present 后必须等开发者明确回复再 decide；若开发者在需求轮**主动**提前答复存储，可当场 present+decide 落定，无需拖到 plan。
- **技能包不含云服务技能 → 不提问，但必须主动告知**：云服务不是可用选项，直接预填 `choice=B`（`note=技能包不含云服务部署能力，默认本地存储`），不进入前沿、不提问；**同时必须主动告诉用户**——没有云服务能力，数据只能存在本地（浏览器/本机），换设备或清缓存会丢、无法做真实跨用户排行，我先按本地保存/纯展示做，后续需要云端保存再加；告知内容写入需求单「部署决策」节「本地存储告知」行（门禁强制检查）。
- 记录纪律：任何落定必须有依据——技能包不含云服务技能 → note 写技能包事实；含云服务技能 → note 写开发者明确回复；没有任何依据时禁止替开发者拍板。
- 确认不需要云服务时，交付走「纯静态 H5（可接虎扑现有业务接口）」路线，**禁止假装有云后端**（不写假接口、不用 localStorage 冒充、不部署空壳函数）。
- 部署节点落定时序：含技能 → 需求阶段标 `deferred`，plan 预览确认后引导式确认存储方式（云端保存/本地保存，带推荐），写入需求单，之后不再反复；不含 → 首版预填已决 + 主动告知本地存储。

## 三、引导原则

1. **问问题看「树」，不看「清单」**
   决策之间有依赖：先问「前置已定」的，再问依赖它的；结束标准不是「清单问完」，而是「没有未问就默认的东西」。落地为：`activity/decisions.json` 决策树 + `state.py tree/decide` 机制——前沿由脚本计算、依赖未定由脚本拒绝、门禁强制待定清空，不依赖提示词自律。
2. **确认前亮出「我替你默认的」**
   预填 80% 解决了「别让用户填空」，但用户可能不知道我们默认了什么。确认前把静默假设列成清单，一句话即可推翻。这是「真实意图」的最后一道保险。
3. **范围由目的地决定**
   先一句话锚定活动最终要什么；超出目的地的不是待问问题，是 out-of-scope。问题说不清楚时先收敛再问，不把「没想清楚」拆成一堆假问题。
4. **每条规则必须对应一个真实失败**
   硬规则如果不能回答「它防什么失败」，就是复杂度的来源。新增规则前先问：这个失败我们真的遇到过吗？

## 四、技能市场与引导层的关系

- 开发者只确认**业务事实**（要什么、规则、体验），从不确认技术方案。
- Agent 在 plan / implement 阶段自行到 `skills/colorbox-skill/SKILL.md` 能力总览里挑选实现能力（虎扑业务接口、跳转、分享、埋点、云服务等）。
- 提问时**禁止问「用哪个能力」**；能力选择是 Agent 的事，不是开发者的事。
- 技能市场是「能力底座」：引导层问出意图后，能力层负责把意图变成可运行页面。
