本文描述**已经落地**的玩法，不是待做草案。可点页面在 `h5/index.html`；规则在 `h5/js/sim/`；经营数字只在 `activity/config.json`，生涯公司/作品/薪资/跳槽只在 `activity/career-world.json`（sync 时并入 `careerWorld`）。目录与接口见 `activity/architecture.md`。

## 1. 经营局玩什么（sim 仍保留）

玩家从 2015 年开一家小工作室，靠招人、立项、做游戏、发售，把公司做到 2025。时间不会自己走，要点「下一月」才过一个月。

公司规模分三档，雇佣人数上限随档位走：小工作室最多 4 人、中等最多 6 人、大公司最多 10 人。升级规模=花钱换场地，由玩家主动花一笔钱从小→中→大，不会因时间到了自动升。每人四维都会用上（程序、剧本、美术、音乐），没有「你是程序所以只加程序」的岗位编制。立项先定题材+玩法，再选主机 / PC / 移动、普通发售 / 长线 / 外包，再安排制作团队：最多 5 人，其中选 1 人当制作人（与「1 制作人 + 最多 4 成员」同一口径）。

粉丝就是业界认不认的那套声望，影响发售后的保底销量，不另做「名声」。市场上有多家对手厂商（名单与展示名只来自配置 `world.rivals.publishers`）抢三端份额和年度大奖，不当第二玩家。打完 2025，给出这一局的生涯结算。资金变成负数即破产，本局失败。

## 1b. 生涯档怎么走（现行 H5，1995–2025）

玩家是刚毕业入行的职员，不是社长。先写**角色名**（默认文案「阿喵」，不要用公司名「喵扑studio」），再锁一个擅长岗（程序 / 策划 / 美术 / 音乐；制作人岗本版不可选），再从三份开局 offer 里入职：小作坊、稳定大厂、野牌各抽一家（`openingOffer.tiers`）。岗位按擅长锁定，薪资按档位表取整。入职后 `phase` 从 `OFFER` 变成 `PLAYING`。

时间同样要点「下一月」。玩家**不能**招人、换场地、广告、立项、发布、关服；这些入口在生涯档 UI 里关掉。能做的是：看自己所在组的在研、每月贡献主职维、处理开发/热修抉择、年底申请跳槽、被挖时接/拒/还价。关掉再打开自动接着玩。结算不分享。

- **在研**：优先挂到本公司本工作室、当前年月正在开发的目录作品（`careerWorld.titles` + `titleDetails`）。空窗超过配置月数则从词库抽一部虚拟作（不要抢同公司同月 landmark 档期）。组里是 5 人：制作人 + 四职，玩家占锁定岗，其余复用本公司同事池。
- **每月**：在研时给锁定维加贡献（基础 + 个人题材/玩法熟练度加成）；可出开发事件（通知或抉择）。目录作发售当月：玩家仍署名则进入**后续支持**若干月（热修事件），TGA/媒体在发售当月评，不另立项。跳槽已不署名则不进后续支持。
- **钱与声望**：月薪入积蓄；本版 `deductLivingCost=false`。声望/荣誉跟履历和奖项走，不是公司粉丝。薪资每年按技术/声望/职级/通胀重算后夹到档位，禁止零头。
- **两套熟练度**：工作室 `studioXp` 抬作品 live 四维底（立项时）；玩家 `genreXp` / `gameplayXp` 只加主职维 live 底和每月贡献。公司历史作会预种 XP。开发月、发售、后续支持都可加玩家 XP。
- **跳槽**：每年 12 月给出最多 5 格 offer，内部工作室调动最多 2 格且排在前面。一次只能申请一家，按公司实力掷骰；失败记 `hopFailedYear`，本年不能再投。本版允许开发中途跳槽。年中挖人（invite）必成：接受则跳槽，还价则现薪跳档并加一点声望，留下则清空邀请。
- **成长**：本版锁在职员（`growthStages.founder` 标注 `lockedThisVersion`）。不当制作人、不开自己的公司。
- **世界发售**：点月按目录把本月该出的作品写入 `worldReleased`（含长线身份与峰值）。带移动端的长线仍按经营局同一套版本规则推 `原神.2.0` 这类标签，日历用 `careerYearReleases`。畅销榜/盒装掉榜在生涯档不跑经营局那套。
- **评奖**：每年 11 月过月。盒装奖看窗口内已发售目录作；最佳长线看已发售且仍在运营的长线，不限于发售当年。读 `titles[].stats` / `score` / `releaseType`，不读空的 `titleDetails.awards`。
- **终点**：推进到 2025 年 12 月结束后 `SETTLED`。结算看角色名、声望、署名作品数、荣誉、积蓄、成长阶段。没有公司破产线。

点月之前，生涯档玩家可以做这些操作（不会自己发生）：

1. 要不要申请年底 offer / 内部调动（先点选一家再申请）。
2. 被挖时要不要跳槽、还价或留下。
3. 开发或热修抉择（过月 queue 里点选项）。
4. 点「下一月」。

禁止自动过月。目录作与虚拟作的发售日由规则表推进，不走经营局的「待发售点发布」。

## 2. 经营局怎么走（2015–2025，点下一月）

- **开局**：2015 年 1 月，小工作室。公司名默认「喵扑studio」，玩家自己写、可改。平台三端（主机 / PC / 移动）都可选；自研主机不是第四选项，达标后并入主机端。不能立项长线运营，但可以接外包练级。自动记录进度，关掉再打开接着玩。生涯结算不分享。
- **核心循环**：看人才市场招人 → 立项（题材+玩法 → 主机/PC/移动、普通/长线/外包、短中长周期 → 最多 5 人含制作人）→ 每月点「下一月」推进开发 → 自制完工先进入待发售（`readyToShip`），玩家点「发布」才结算（媒体评分、写入基准销量、当月实销、三端份额）；外包到期自动交付经验与外包费 → 用收入发薪、再立项。中等公司起可立项长线；大公司可成立内部工作室，多项目并行，但点月仍然只点一次。
- **终点**：推进到 2025 年 12 月结束后，强制出生涯结算（作品、系列、最高纪录、公司规模/粉丝、有没有摸到自研主机门槛）。资金先变成负数则提前破产失败。不是「做满 5 年或 5 款就结束」。
- **更长档**：经营局不把 2005 / 1985 开局做成可选项；生涯档已经从 1995 开打。

点月之前，玩家可以做这些操作（不会自己发生）：

1. 要不要招人、辞退；编制受当前规模上限限制（4 / 6 / 10）。
2. 要不要花钱换场地，从小工作室升到中等、再升到大公司（金额见 activity/config.json）。
3. 要不要做广告营销（花钱加粉丝，并加持「下一款发售的那一部」销量；发售后消耗）。
4. 空闲的人要不要立项（自制发售 / 长线 / 外包接活）；已有工作室的，负责人默认当制作人。
5. 自制游戏做完进入「待发售」后，要不要点「发布」（才走媒体评分、销量、长线转入维护、广告加持、三端份额）。可同时积压多部，上限见配置。
6. 长线游戏要不要安排/撤走维护人员；人撤走或不安排人 = 终止运营（关服）。
7. 大公司阶段要不要成立内部工作室。
8. 点「下一月」，把所有在研、长线、发薪、事件按第 9 节顺序走完。

禁止自动过月：没有玩家点击，时间、开发、发薪、破产判定都不走。外包接活到期仍自动交付（合同），不走「暂缓发布」。

## 3. 公司

公司是这一局的存档主体，记「现在这家公司长什么样」，不记某一款游戏的制作细节。

| 字段 | 说明 |
|------|------|
| 公司名 | 玩家自己写；开局默认「喵扑studio」，可改 |
| 当前年月 | 2015.01–2025.12，只在点「下一月」时 +1 |
| 资金 | 发售/长线进账；发薪、换场地、广告、研发、长线固定开支出账。发薪仍每月扣；扣穿资金为负数 → 破产，本局失败。没有「发不出工资先裁人」的缓冲失败线 |
| 规模 | 三档，影响雇佣人数上限，也是长线、内部工作室、自研主机的门槛。升级=玩家主动花钱换场地，不是时间到了自动升 |
| 粉丝 | 类似声望，与「名声」并成一套：影响游戏发售后的保底销量；广告、高分、大奖、事件可以抬粉丝。不另做第二套声望 |
| 员工 | 名单；人数不得超过当前规模上限 |
| 内部工作室 | **只有大公司阶段可以成立**。没有工作室时，项目挂在公司名下 |
| 已解锁平台 | 三端主机 / PC / 移动，开局都可选；自研主机另有大公司门槛，达标后并入主机端 |
| 往期作品 / 系列 | 指向已发售游戏列表与系列档案，不是再抄一份制作字段 |
| 广告加持 | 存档字段是 `company.adOn`。若已花钱做营销：加持「下一款真正点发布的那一部」；该部发售后消耗，不自动挂到再下一款 |

对手不做成第二玩家。总览与情报页展示当月出货、畅销榜、发售日历（见第 8 节）。早稿「N 社 / S 社两家简表」已废。

### 规模档（已决）

| 档位 | 雇佣上限 | 解锁 |
|------|----------|------|
| 小工作室（开局） | 最多 4 人 | 不能立项长线；不能成立内部工作室；不能自研主机。满编队是 5 人，小工作室做不满，最多 1 制作人 + 3 成员 |
| 中等 | 最多 6 人 | **可以立项长线运营**（门槛就是升到中等，不是含糊的「做大之后」） |
| 大公司 | 最多 10 人 | 可继续做长线；**可以成立内部工作室**；自研主机入口在这一档才开放 |

换场地金额、广告花费与加成、自研主机粉丝门槛等具体数字见 activity/config.json。

## 4. 角色（员工）

没有「策划岗 / 程序岗」。人就是人：四维都会用上，差别在高低和特性。

| 字段 | 说明 |
|------|------|
| 姓名 | 展示用 |
| 等级 | 做游戏攒经验，经验满了升级；升级只加四维属性，不解锁、不改变特性 |
| 程序 / 剧本 / 美术 / 音乐 | 四维属性。立项后都贡献给这款游戏，不是只贡献自己的「主职」。旧稿「策划」改口为「剧本」，并加上「音乐」 |
| 特性 | **天生**：雇佣时就带上（人才市场刷新时随机抽出），不靠养成获得，也不靠升级改变 |
| 荣誉 | 获奖、高分作品给角色荣誉；荣誉抬薪资预期（幅度见配置） |
| 薪资 | 每月点月时发放；随等级、技术和荣誉成长；**每年进入新年时调整一次** |
| 工龄 | 在本公司待了几个月；影响忠诚/跳槽事件和薪资预期 |
| 状态 | 空闲 / 开发中 / 长线维护 / 负责工作室 |
| 当前项目 | 空闲则为空；制作人、开发成员、长线维护都算占坑 |
| 是否工作室负责人 | 负责人默认就是该工作室在研项目的制作人 |

占用规则：同一人不能同时参加两个项目，也不能一边做新游戏一边维护长线。当制作人、当成员、当长线维护，都占整月。点月期间人不空出来，就不能再塞进别的组。

### 雇佣 / 辞退 / 人才市场

- 员工有月薪；招进来按月发，辞退即离队、不再发薪。
- **每月**人才市场刷新一批可雇员工（随机等级、属性、特性）。招不招是玩家点月前的操作；编制受公司规模上限限制（4 / 6 / 10）。
- 招满了就不能再雇，除非先辞退或先花钱升规模。

### 角色养成（已决）

养成 = 做游戏攒经验升级（只加属性）+ 天生特性在开发里生效 + 薪资/荣誉随作品与大奖成长。

- **没有单独培训界面**，也不靠「送去培训」获得特性或升级。
- 特性是入职自带的，升级不加新特性、不改已有特性。

### 特性（获得方式已决；效果数字见配置）

特性天生，雇佣时从配置池抽出；升级不加新特性、不改已有特性。一个人可以 0～2 条（条数权重见 `talentMarket.traitCountWeights`）。不必做特性冲突表。

现行 8 条，效果数字只在 `config.traits`：

- **灵光一闪**：开发过程中有机会来一次「灵感月」——当月某一维额外往上跳一截，但不是每月都有。制作人身上更容易触发；成员按人各自判定，触发时加成较小。
- **一丝不苟**：成品更稳，翻车（评分大幅低于预期、事故）更少；代价是开发里更少「赌爆款」。制作人有这特性时，整款游戏的稳定性吃满；成员有则只抬自己那一份。
- **肝帝**：做游戏和养长线都额外攒经验，升级更快。
- **人气王**：作品真正点发布时多带一截粉丝；制作人加成更大。外包交付不触发。
- **省钱怪**：算薪时乘 `salaryMult`，同样能力更便宜。
- **气氛组**：在组里时，整月有机会给在研某一维加一截（每人每月最多按最高那条计）。
- **跟风选手**：发售对上当月潮流时，基准销量在潮流倍率后再乘一截。
- **长线操盘**：去维护长线时，月收再乘一截。

触发率与加成见配置。人才市场和总览要能看见特性名，招人时才有判断。

## 5. 立项与在研

「在研」是制作单：还没卖、还在做。不要和发售后的销量报表混在一张卡上。

立项顺序：先定题材 + 玩法，再选平台端、类型、周期，再安排制作团队。

| 字段 | 说明 |
|------|------|
| 题材 | 随时间或事件解锁。名单与解锁年见配置 |
| 玩法 | 随时间或事件解锁。名单与解锁年见配置 |
| 游戏平台 | **三选一：主机 / PC / 移动**（id：`console` / `pc` / `mobile`）。2015 开局三端都可选，不按规模再锁平台。**已废**：玩家点 PS4、Xbox、Switch 等具体机种。机种只可能出现在对手配置文案里，不是立项选项。自研主机达标后并入「主机」端加成，不是第四个玩家选项 |
| 类型 | 自制普通发售 / 自制长线运营 / **外包接活**。立项时锁死，中途不改。**小工作室不能立项长线**，但可以接外包；必须已是中等公司才能长线 |
| 开发周期 | 玩家立项时选择短 / 中 / 长。各档月数见配置（外包可另配，缺省沿用同一套） |
| 系列 | 仅自制发售：若媒体均分达到配置门槛可开新系列作。外包不进系列。见第 6 节 |
| 制作人 | 必须 1 人。无工作室时玩家来选；有工作室时默认是负责人，不必再另选 |
| 开发团队 | **最多 5 人含制作人**（1 制作人 + 最多 4 成员；可不足员开工，质量会吃亏）。外包同样占编 |

在研过程中另外只记这些「制作中」状态：

| 字段 | 说明 |
|------|------|
| 剩余月数 / 进度 | 点月推进；总开发月数在立项时由短/中/长锁定 |
| 当前四维 | 立项时拷贝制作人四维为游戏基础属性，之后每个过月按第 5.1 节加算 |
| 占用人员 | 制作人 + 成员，点月期间不可兼职、不可去维护别的长线 |

### 5.1 游戏质量怎么算（已决；删除旧的 2:1 加权合计）

四维现为：**程序、剧本、美术、音乐**。不要再用「策划 / 美术 / 程序」三项，也不要用「制作人权重 2、成员 1、三项合计」。

用业务语言按月加算，算法如下。

**立项时**

1. 玩家选好题材、玩法、平台端（主机/PC/移动）、普通发售 / 长线 / 外包、开发周期（短/中/长）。
2. 安排最多 5 人，其中 1 人当制作人。
3. **游戏基础属性 = 制作人当时的四维**（立项时拷贝一份到这款游戏上）。

**每个过月（对四个维度分别做）**

1. 先算制作人的贡献：对该维，在 1 到「制作人该维当前属性」之间随机一个整数（含两端）。本月该维增加 = 向上取整（随机值 ÷ 总开发月数）。总开发月数由立项时选的短/中/长决定，月数见配置。
2. 再对每个成员用同样方法：随机 1 到「该成员该维属性」，再 ÷ 总开发月数、向上取整，加到游戏该维上。
3. 特性、当月事件可以在这一月额外改某一维或总体（与事件系统衔接；加减幅见配置）。

**开发完成**

各月加算累加之后的四维，就是这款游戏的属性。自制（普通发售 / 长线）`monthsLeft` 到 0 **不会自动发售**：制作组释放为空闲，游戏进入 `readyToShip`（待发售）。未点「发布」前不算发售、不弹媒体分、不占市场份额、不消耗广告加持。玩家在点月前点「发布」才走媒体评分、销量、长线转入维护。可同时积压多部；配置有 `release.readyToShipMax`，现行 sim 完工时一律入队、未按该上限拒收。

外包接活到期仍自动交付（合同），不进待发售。

演算示例的具体数字见 activity/config.json 的 `exampleQualityRoll`（算法仍以本节为准）。

人数不满不是不能立项，而是每月少几份加算，某一维更容易塌。制作人弱、成员强，成员每月仍按自己的属性随机贡献，能托底，但游戏起步拷贝的是制作人四维。

### 5.2 外包接活（练级攒经验）

外包是立项里的第三条路径，不是长线，也不是抽卡或真实劳务。小工作室就可以接。同时进行的外包单数量上限见配置。

- 仍选周期与制作组，仍占编制，点月仍按第 5.1 节加算质量并给参与者经验（外包每月经验可另配，缺省高于自制开发）。
- **不**走媒体五家评分、**不**进系列、**不**消耗广告加持。对三端市场份额的计入权重见配置，默认不占份额。
- 完工发一笔外包费（固定底 + 按质量区间，公式与上下限见配置），放人。外包费应明显低于一款自制发售，主收益是练级而不是赚钱。
- 过月队列提示「外包交付 +经验 +外包费」，不弹媒体评分面板。

## 6. 已发售游戏、长线、系列

发售之后，这款游戏从制作单变成作品档案。基础信息还在：题材、玩法、制作人、制作团队、平台、所属系列、发售年月、四维、媒体评分。

### 普通发售（盒装 Logistic 生命周期）

| 字段 | 说明 |
|------|------|
| 基准销量 `baselineSales` | 点「发布」时用发售公式算出的 **首月参照**（粉丝保底 + 质量合计 + 广告 + 潮流 + 系列/自研主机等，系数只读 `release` / `series` / `company`）。这是 Y 曲线去乘的基数，**不是**这个月账上实际进了多少。少数事件可以改基准（乘或加减），改完之后后续月都用新基准 × Y(m) |
| 发售当月实销 `launchSales` | 发售当月真实销量，进资金。可以被「只砸当月」的事件改写，**不得**回写基准，否则 2–12 月会跟着崩。**已废**：把 `launchSales` 当后续月乘数基数 |
| 当月真实销量 | `round(baselineSales × Y(m) × 当月瞬时修正)`。进资金、进畅销榜、进份额 |
| 生命周期 Y(m) | Logistic，参数只读配置 `lifecycle`：`tMin` `tSpan` `x0Min` `x0Span` `k` `scoreMin` `scoreMax` `maxMonths`。评分 S = 媒体均分；无均分不套最高分。长线/外包不走这条曲线。**已废**：指数长尾、`tailLeft` 倒计月（旧档字段 tick 时忽略并迁移） |
| Y 公式 | 令 x = m−1，u = (S−scoreMin)/(scoreMax−scoreMin) 夹在 0～1，T = tMin + u×tSpan，x0 = x0Min + u×x0Span，则 Y = T + (1−T) / (1 + e^(k·(x−x0)))。k 不随评分变。实现认公式，不算 12 格查表 |
| 掉榜停售 | 先结算本月实销，再按实销排 `lifecycle.chartSize` 席（不足用配置 `chartFillers` 假游戏填满）。**未进榜**的盒装停止发售（不再产生月销、离开在售）。发售当月先入账再参与榜，再决定下月是否还卖。`dropOffY` 不参与停售，避免榜内作品被 Y 提前杀掉。`maxMonths` 只让 Y 变为 0（实销 0 则排不进榜） |
| 畅销榜 | 按 **本月实销** 排序，席位 `lifecycle.chartSize`；本公司在售盒装 + 仍在运营的长线 + 对手在售 + 假游戏。假游戏只占席，不是玩家可经营实体。情报「市场」页与总览可看 |
| 人员 | 完工进入待发售时占用人员已释放；点发布不再占编 |

发售公式（写入 baseline，不把结果当后续乘数）：粉丝 × `fanSalesCoeff` + 四维合计 × `qualitySumSalesCoeff`，再乘广告 `nextReleaseSalesMultiplier`（若 `company.adOn`）、潮流 `trendSalesMultiplier`（题材或玩法对上任一）、系列 `guaranteedSalesInheritRate`（有 `seriesId` 时）、自研主机 `ownConsoleSalesMultiplier`（主机端且已解锁）。配置里的 `series.fanInheritRate` 现行 sim 未读。

### 长线运营（已决）

可以做长线运营游戏：发售后仍要安排人持续维护和迭代，有固定开支成本。**一开始不能做**；**必须中等公司才可以立项长线**。小工作室不能做。

| 规则 | 说明 |
|------|------|
| 占编 | 维护占坑，不能同时做新游戏。至少安排 1 人占编维护，长线才继续开着 |
| 人走就关服 | 人撤走（或不安排人）= **终止运营**。不要写成「只扣钱不占人」 |
| 固定开支 | 每个月从公司资金扣，与发薪分开；金额见配置 |
| 产出 | 点月时先有维护产出（质量/内容迭代的当月效果），再在长线月结里算收入与固定开支 |
| 终止运营 | 玩家可主动关掉一条长线；维护人员被撤走或不安排，效果等同关掉。**掉出畅销榜**也关服，走现有 `shutdownLiveOps` / `shutdownLive`（放人、停月费、开支罚金） |
| 版本发售 | **带移动端**的长线按大版本.小版本继续发售（如 `原神.2.0`），不是新立项。1.0 是首发；之后每隔配置间隔发一版，满若干小版本进下一档大版本。日历、过月通知会标出版本；大版本再评一次媒体。经营局当月月收按配置抬一截。关服后停止。纯 PC / 主机长线不走这套 |

长线的最高纪录指「曾经最高月收 / 最长运营」，和普通发售的销量纪录不是同一个意思。版本号只是同一部长线的多次发售，不另开系列。

### 系列续作（已决口径；门槛数字见配置）

这是「一个系列」，不是单个作品的剧情续作。像马里奥 2 / 3、GTA：故事无强制关联，不用先玩 4 再玩 5。

覆盖旧稿「指定前作、连作衰减」里偏单线续作的表述：

- 系列有名称、作品列表、系列声望。
- 若媒体均分达到配置门槛，发售时可自动开系列新作（`maybeOpenSeries`）。
- 新作发售公式按 `guaranteedSalesInheritRate` 抬销量。不要写成「指定前作 × 连作衰减」。配置项 `fanInheritRate` 现行未接入公式。

## 7. 工作室（仅大公司）

**只有大公司阶段可以成立内部工作室。** 覆盖旧稿「做大之后」的含糊门槛。

- 工作室有名称、负责人、当前在研（可以没有）。
- **负责人默认就是该工作室在研项目的制作人**，立项不必再另选制作人。负责人换人 = 这间工作室的制作人换人。
- 工作室人数仍算在公司当前规模上限里（大公司最多 10 人），不另开编制。
- 点「下一月」时，**所有工作室的在研项目一起推进**，玩家不用按工作室分别点月。
- 第一版建议：工作室数量以编制能养活为准；空壳工作室可以有，但不占制作人以外的额外规则。

没有工作室时，行为与「公司直营一队」相同：玩家每次立项自己指定制作人。

## 8. 平台、对手、潮流、媒体、年度奖

### 平台

- 玩家只选三端：**主机 / PC / 移动**。2015 开局三端都可选。
- **已废**：立项选 PS4 / Xbox / Switch 等具体机种。题材、玩法仍可随时间或事件解锁（名单见配置）。
- **自研主机**：只有公司规模已经到「大公司」才解锁，并另需粉丝达到配置门槛。达标后 `company.ownConsole = true`，并入「主机」端（销量加成见配置），不出现第四个立项选项。升不到或粉丝不够，本局就没有这条加成。

### 广告营销

玩家点月前可花钱做一次营销：

- 立刻提升公司粉丝；
- 并加持「下一款发售的那一部」的销量（不是加持在研里随便指定的一部，就是时间上下一款真正发售的那部）；
- 该部发售后，这次加持消耗掉。

花费、加多少粉丝、销量倍率见配置。

### 题材热点潮流

第一版随机刷新（间隔、持续、销量倍率见配置）。发售时，题材或玩法对上当月潮流的游戏，销量按配置倍率提升。事件可以把潮流改成指定题材或玩法；总览写「玩家开始喜欢 xx」。

### 市场份额

按三端拆开：主机、PC、移动。每一端展示本公司累计销量 vs 全市场（本公司该端累计销量 + 对手该端累计出货）。公式见配置。自制普通发售与长线计入对应端；外包默认不计入。对手出货必须带平台端，点月后份额会变。对手不当第二玩家，不做他们的招人/立项界面。

### 本月畅销榜

按 **本月实销** 排序，席位数见 `lifecycle.chartSize`。包含本公司仍在售的盒装、仍在运营的长线、对手本月出货与仍在售的盒装，以及配置里的假游戏（`lifecycle.chartFillers`）。席位不够就用假游戏填满；玩家作品必须把假游戏挤下去才算上榜。假游戏被挤出榜后只是不再出现，不是玩家可经营的实体。

点月时序：先结算本月实销（盒装 Y 曲线、长线月收）→ 再排榜 → **未进榜**的盒装停售、长线关服、对手在售也离开榜席。不要先停售再排榜。`dropOffY` 不再作为停售条件。

### 对手（多厂商日历，不当第二玩家）

对手名单、展示名、系列、三端权重只来自配置 `world.rivals.publishers`。不当第二玩家，不做他们的招人/立项界面。点月时按**发售日历本月计划**出货，再走与玩家盒装同一套 Y 曲线。

**已废**：只有「N 社 / S 社」两家简表、点月另骰一套与日历无关的随机发售。

每条出货带平台端（console / pc / mobile），计入该端累计出货，点月后三端份额会变。

**其他厂商发售日历**

- 日历只记对手/其他厂商，不含玩家自己的待发售（玩家仍看待发售列表）。
- 开局 2015.01 时已生成当年 1–12 月计划，否则第一年没表可看。
- 每年 12 月点「下一月」、走完 12 月结算并翻到下一年 1 月之后，生成「后 1 年」全年计划（例：2016.12 → 2017.01 时生成 2017 年 1–12 月）。
- 每月可以 0～N 部，数量只来自配置；不要每月塞满，也不要整年空白。历史必发作（如 2017.9 K 社《吃鸡》）写入对应年月，不靠骰子漏掉。
- 点月真正出货时执行日历上「本月计划」，不再另骰一套无关随机发售。事件「对手提前到下个月」会改日历：把该作从原计划月挪到下月（或插入下月）。
- 带移动端的长线会按版本继续出现在日历上（如 `原神.2.0`），不是新立项。经营局本公司长线版本也会标出来。纯 PC / 主机长线不走版本。
- 生成走局内 rngSeed，同年同 seed 可重放。旧年表不必存十年全文，保留年数见配置。

### 游戏媒体评分

每部游戏发售后弹出媒体评分面板：

- **5 家媒体**各打一份分；
- 对外第一版用化名（名单见配置），不要把真名写成必须上线的设定；素材里可以写「气质接近常见评测媒体」；
- 面板下方有一段随机媒体人点评。

五家怎么从四维收成分数：按各媒体对四维的权重折成 1–10 分（系数与化名名单见配置）。

### 年度奖（TGA 味）

**每年 11 月过月时触发**（覆盖旧稿 12 月颁奖）。

- **盒装奖**（年度游戏、最佳玩法/叙事/视觉/配乐、玩家之选）：参选 = **去年 12 月～今年 11 月** 窗口内已发布作品。外包不参选。
- **最佳长线运营**：只收长线（`releaseType=liveops` / 玩家 `liveOps` / 对手 `live`）。已发售且仍在运营（或本届窗口内关服）即可，**不限于发售当年**。按长线峰值比，没有峰值时用四维合计兜底。生涯目录读 `titles[].releaseType`，不要只读 `titleDetails.liveAfterRelease`。
- 长线首发仍可进盒装窗口；往年还在运营的长线只进最佳长线，不占年度游戏席。
- 2015–2025 经营局与生涯档都用同一张奖项名单（见配置）。奖杯抬粉丝与角色荣誉，不直接发真实奖品、不涉及钱。玩家之选读的是 `launchSales`（发售当月实销），不是 lifetime。

### 事件系统

事件按 **来源** 和 **表现** 分类，字段写在配置里，逻辑认这些字段。数字（概率、加减幅、选项效果）只在 json。

**来源**

- `random`：点月时按 `monthlyEventChance` 从随机池按权重抽一条（可与历史事件同月并存）。
- `historical`：有绝对年月或因果前置（`after.prevEventId` / `after.releaseTitle`+间隔月），到点必触发（或配置了 chance 则掷骰），不是纯日历骰子。每条历史事件一局只触发一次。

**表现**（只决定 UI，不决定效果能不能发生）

- `notice`：通知类，只有确认。点月时立刻 `applyEventEffects`（`duringTick: true`，销量修正留给 lifecycle 结算）。
- `choice`：抉择类，选项绑定效果；玩家必须选一个才继续过月队列。选项效果走 `resolveEventChoice`，UI 禁止自己改资金。现行随机抉择包括赶工、请人播、周末加班、包体流出、渠道分成、差评回复。

**五种效果族**（可组合；数字只在 json）

1. **公司**：`fansDelta`（可正负；已发售作品的基准 **不会** 因粉丝变化被重算）、`fundsDelta`。
2. **在研**：`devMonthsDelta`（只作用于仍在研、`monthsLeft > 0` 的项目，待发售不受「延长开发」）、`qualityDelta` / `qualityDimDelta` / `qualitySumDelta`（现行都是给在研某一维加减，不是四维各加一遍）。
3. **对手**：`rivalAdvance` 把日历上该社未发计划挪到下月（可指定系列）；`rivalRelease` 按脚本立刻出货（用于历史发售）；`setRivalMau` 写入该作 `mau` 供情报展示。**别人家提前发不改玩家 baseline。**
4. **潮流**：`setTrend` 立刻把当月潮流设为指定 `genreId` 或 `gameplayId`。总览显示「玩家开始喜欢 xx」。自制发售对上题材或玩法任一即吃潮流销量加成。随机刷新仍抽已解锁题材。
5. **盒装销量**（两套，文案必须写清）：
   - 只砸当月实销：`monthSalesMult` / `monthSalesDelta`。只改本月 `round(baseline × Y(m) × 修正)`，**不改** `baselineSales`。下月仍按原基准 × Y。
   - 改基准：`baselineSalesMult` / `baselineSalesDelta`。改该作（默认 `salesTarget=playerOnSale`，也可用 `targetTitle`）的基准，之后每一月都用新基准 × Y(m)。

点月时：通知类事件先把销量修正写到在售盒装上，再走 lifecycle 用 Y(m) 结算（发售当月若已在点发布时入过账，只补差额）。不要「事件先改粉再重算 baseline」，除非该事件带了改基准字段。

示例：随机通知「渠道故障」只砸当月；「口碑反噬」改基准；赶工抉择里「先清仓赶工」也只砸当月实销。请人播里「花钱买量」只抬当月实销。

**因果链（表驱动，不要只改文案）**

配置 `historicalEvents`。吃鸡链（大逃杀玩法 2017 年解锁，链不早于该年）：

1. **2017 年 9 月**：对手历史发售《吃鸡》（K 社），`rivalRelease` 写入日历对应月，不依赖随机出货。
2. **2017 年 10 月**：通知《吃鸡》引爆市场。`setRivalMau`：总览/市场/情报能读到该作 **月活**（state 里该 rival 记录的 `mau`），不是一句 toast。
3. **2017 年 11 月**：`setTrend.gameplayId=battleRoyale`，市场开始喜欢 **大逃杀**。之后自制大逃杀吃潮流加成。

另有：2015.10–11《王者荣耀》上线 → MOBA 潮流；2016.6–7 武侠刷屏 → 武侠潮流；2018.6–7 自走棋杀出模组区 → 自走棋潮流；2020.2 居家把在售盒装当月实销抬高（不改基准）；2020.9–11《原神》上线 → 月活 → 奇幻潮流；2022.8 窗口变窄（历史抉择）；2024.8 国产单机神话刷屏 → 神话潮流。随机池还有若干通知和多条抉择，证明系统是通用表驱动。

过月 queue 用现有弹层。抉择页选项按钮调用 sim，再继续 queue。

## 9. 点月时结算顺序

`tickMonth` 若 `state.mode === "career"` 则整段改走 `tickCareerMonth`（见 9.2）。经营局按下面顺序走完（与 `tickMonth` 一致）。所有工作室共用这一次点击。广告、换场地、招人/辞退、**发布待发售**、关服、开工作室都是点月前的操作，不插进下面自动步骤里。**已废**：完工自动发售。

1. **推进在研**（第 5.1 节质量加算 + 特性）+ **长线维护产出**（维护人员加经验、长线作品某一维 +1）。推进在研 ≠ 自动发售。
2. **潮流刷新**（若该月该刷）→ **当月事件**（历史到点 + 随机池）。通知类当场套效果；抉择类本步只入队。
3. **对手出货**：执行日历上「本月计划」（`shipRivals`），历史 `rivalRelease` 若本月出货则并入。写入对手 `baselineSales`，走同一套 Y。
4. **到期处理** → 自制普通发售/长线：进入 `readyToShip`，制作组空闲，queue 提示尚未发布，**不**弹媒体评分。**外包**：到期仍自动交付，不走暂缓发布。玩家在点月前用 `releaseGame` 才：媒体五家评分 → 写入 **baselineSales** → 当月实销 = round(baseline × Y(1)) 入账；长线发布时原班人仍空闲则转入维护。
5. **盒装 lifecycle + 长线月结**：玩家与对手在售盒装当月实销 = round(baselineSales × Y(m) × 当月瞬时修正)；发售当月已入账则只补事件差额。长线：收入、固定开支、占人；无人则关服。带移动端且仍在运营的长线若本月轮到版本，走版本发售（日历/通知/大版本媒体；经营局抬当月月收）。然后按本月实销排畅销榜（含假游戏）写入 `monthChart`；未进榜的盒装停售、长线走关服、对手在售离开榜席。
6. **发薪**：按在职员工薪资从资金扣除。**资金 < 0 则破产失败**，本局提前结束。
7. **若本月是 11 月**：TGA 评选（盒装看窗口内已发布；最佳长线看仍在运营的长线），改粉丝与荣誉。
8. **人才市场刷新**一批可雇员工。
9. **日历 +1**；若刚进入新年：年薪调整，并生成刚进入的这一年的其他厂商发售表（12→1，`ensureRivalCalendar`）。开局已生成当年表。若已过配置结束年月 → 生涯结算。

禁止自动过月。`applyLongTail` 只是 `tickLifecycle` 的兼容别名，不是指数长尾。

### 9.2 生涯档点月（`tickCareerMonth`）

1. 补齐存档缺字段；没有工作室 id 则落到该公司默认工作室。
2. **后续支持中**：给当前作出玩家 XP，掷热修事件（抉择入队）。**在研中**：主职维加月贡献，给玩家 XP，掷开发事件。待命则跳过产出。
3. **世界发售**：本月目录作写入 `worldReleased`；已在售的移动端长线按版本规则推进。
4. 若玩家仍署名的作品本月发售 → 结算署名、口碑、后续支持，媒体/奖项入队。
5. **发薪**：月薪入积蓄；配置要求时再扣生活费。把积蓄镜像到 `company.funds` 仅供 UI 复用，不走破产。
6. **若本月是 11 月**：生涯 TGA（盒装窗口 vs 长线运营池）。
7. 年中挖人：按配置概率最多入队一条邀请。
8. **12 月**：生成年底 offer 表；不在后续支持中则入队跳槽页。
9. **日历 +1**；若刚进入新年：按新年重算月薪档。后续支持月数 -1，耗尽则卸下当前作。空窗累计后 `assignCareerProject`（目录或虚拟作），刷新同事。
10. 已过 `careerWorld.timeline` 结束年月 → `SETTLED`。

## 10. 第一版不做 / 已废

- 经营局年限 2015–2025；生涯档 1995–2025。更早的 1985 档不进本版。
- 生涯档本版不当制作人、不开自己的公司（创始人阶段锁定）。
- 雇佣上限按规模：4 / 6 / 10；立项最多 5 人含制作人；不能兼职两个项目，也不能边做新游戏边维护长线。
- 时间只许手动点「下一月」。
- 不做岗位编制、单独培训界面、特性养成解锁。
- 小工作室不能立项长线；未升到大公司不能成立内部工作室。
- 自研主机有大公司 + 粉丝门槛；达标后并入主机端，不作为第四个玩家选项。
- 外包接活是练级途径，不是抽卡，也不涉及真实劳务或提现。
- 对手不做第二玩家。
- 不涉及真实金钱、奖品、抽奖。
- 生涯结算不分享到微信/微博（已拍板）。
- 不做精细立绘。

**已废、不要两套并存：**

- 发不出工资先裁人；名声与粉丝两套声望；制作人权重 2:1 三项合计；长线只扣钱不占人；指定前作的单线连作衰减；12 月颁 TGA。
- 玩家选项里的 PS4 / Xbox / Switch；只有 N 社 / S 社两家简表。
- 自制完工自动发售（现行必须点「发布」）。
- 指数长尾、`tailLeft` 倒计月。
- 用 `launchSales` 当 2–12 月销量乘数（后续月只用 `baselineSales` × Y(m)）。
